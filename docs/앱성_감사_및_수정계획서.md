## 2부. '앱성' 에이전트 구조 설계

앱성은 **토성 폴더(및 이 저장소)의 앱들을 입력받아 할루시네이션과 버그를 탐지·수정·검증**하는 에이전트다. 1부의 결함 유형이 그대로 탐지 파이프라인 요구사항이 된다.

### 2.1 파이프라인 구조

```
[① 수집기 Scanner]
   앱 파일 목록화 → HTML/JS/데이터/외부주장(법규·API명) 분리 추출
        │
[② 주장 추출기 Claim Extractor]
   규격명·연도·수치기준·API 시그니처·코드-문서 대응쌍을 "검증 가능한 주장" 단위로 구조화
        │
[③ 검증기 Verifier]  ← 할루시네이션 담당
   ├ 지식베이스 대조: 규격 연도/출처(ISO·KBIMS·BCA·BF법), API 존재 여부(Revit/Dynamo/Civil3D)
   ├ 내부 일관성: 데이터↔로직↔UI 삼자 대조 (예: H-08, H-10)
   └ 판정: 확정 할루시네이션 / 출처 오귀속 / 미검증 → 근거 첨부
        │
[④ 결함 탐지기 Bug Detector]  ← 버그 담당
   ├ 정적: 죽은 코드, 인덱스 산식, 경계조건(엡실론), 미사용 반환값
   ├ 수치 검증: 알려진 정답이 있는 소형 지형(평면·단일경사면)으로 각 계산 함수 실행,
   │            해석해와 대조 (경사%·각도·면적·유역)
   └ 런타임 스모크: headless 브라우저로 7개 Step 클릭 시나리오 실행, 콘솔 에러·NaN 검출
        │
[⑤ 수정기 Fixer]
   결함별 최소 수정 패치 생성 → 심각도순 적용 (P0→P2)
        │
[⑥ 회귀 검증기 Regression Gate]
   ④의 수치 검증·스모크 테스트 재실행 → 전건 통과 시에만 커밋
        │
[⑦ 보고서 Reporter]
   결함 ID·근거·수정 diff·검증 결과를 감사보고서(md)로 산출
```

### 2.2 저장소 내 배치(제안)

```
/BIM
├─ BIM_Slope_EL_Automation.html      # 감사 대상 앱
├─ docs/
│  └─ 앱성_감사_및_수정계획서.md      # 본 문서
└─ appseong/
   ├─ knowledge/regulations.json      # 검증된 규격 지식베이스(출처 URL 포함)
   ├─ knowledge/api_signatures.json   # Revit/Dynamo/Civil3D 실존 API 목록
   ├─ checks/claims.test.js           # ③ 주장 검증 규칙
   ├─ checks/numeric.test.js          # ④ 해석해 대조 수치 테스트
   ├─ checks/smoke.spec.js            # ④ Playwright 스모크 시나리오
   └─ run_audit.js                    # ①~⑦ 오케스트레이터 → report.md 산출
```

핵심 원칙:
- **주장에는 출처를, 수정에는 테스트를**: 지식베이스에 근거 URL이 없는 기준치는 앱에 싣지 않는다(미검증 수치는 "참고" 표기 강등).
- **검사는 항상 실패 가능해야 함**: H-05 같은 무조건 통과 검사를 금지하는 린트 규칙 포함.
- **수치 함수는 순수 함수로 분리**: C-02 해소 — `TINSurface`를 별도 모듈로 추출해 테스트 가능하게.
