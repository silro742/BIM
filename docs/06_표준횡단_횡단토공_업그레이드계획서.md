### 0.3 v1.0 계획의 **오류 정정** — 양단면평균법 차단 방침 철회

v1.0에서 “AEA 선택 시 하류 내보내기 차단(P0)”을 제안했다. **이는 국내 기준상 잘못된 요구다.**
앱이 이미 내장하고 있는 `BIM_GUIDELINE_BASIS`에 근거가 있다.

> **국토교통부 BIM 시행지침 설계자편 2.4.2 (2)** — “토공 수량산출 시 원칙적으로 객체화된 BIM 모델에 의한
> 체적법을 적용할 수 있으나, **발주자가 인정하는 경우에는 기존 양단면 평균법을 적용할 수 있다.**
> 수량 기초데이터 신뢰도 확보를 위해 BIM 객체 간 간섭 검토 등 품질검토를 반드시 수행한다.”

따라서 올바른 게이트 설계는 **차단이 아니라 “발주자 인정 근거의 기록 강제”** 이다. 개정안은 F-02에 반영했다.
연구자료(§3)가 지적한 급곡선 왜곡 리스크는 차단 대신 **곡률 보정과 기법 간 편차 경보**로 통제한다.

## 1. 실측 결함 (Defects) — 이번 개정의 핵심

앱 소스에서 직접 확인한 물량·파이프라인 결함이다. 각 항목은 재현 가능한 근거를 함께 적는다.

### D-01 [P0] 포장 구조 두께가 토공 단면에 반영되지 않음
`calcCutArea()`는 `halfRoad × cutH`로 노반부를 계산하고, `pave1·pave2·base·subbase` 입력값은
`drawAssembly()`·`genAssemblyScript()`·`exportHandoff().pavement_total_m`에서만 쓰인다.
UI가 DG를 “도로 설계 표고”(포장 상면)로 정의하므로, **노상 절하(포장 구조 두께)만큼 토공이 누락**된다.

- 기본값 검증: 포장 합계 `0.05+0.05+0.15+0.20 = 0.45 m`, 전폭 `2 × (3.5+1.5) = 10.0 m`
- 측점당 결손 단면적 = `10.0 × 0.45 = 4.5 ㎡`
- 절토고 3 m 기준 현재 산출 단면적 = `2 × (5.0×3 + 5.4) = 40.8 ㎡` → **결손 약 11%**
- 절토고가 낮을수록 비율은 커진다(절토고 1 m 구간에서는 30% 이상).

**조치**: `calcCutArea`/`calcFillArea`에 `subgradeDrop = pavementTotal`을 적용하고, 절·성토고를
`cfh_earthwork = eg − (dg − pavementTotal)`로 재정의한다. 계획고 정의(포장상면/노상면) 선택 스위치를
Step 3에 두고 선택값을 핸드오프에 실어 하류 오해를 차단한다.

### D-02 [P0] 누가토량곡선이 자연상태 절토와 다짐상태 성토를 그대로 감산
`drawMassHaul()`은 `cum += v.cutVol − v.fillVol`로 누가 유토를 그린다. 두 값의 상태가 다르다.

- 성토량은 다짐(Compacted) 상태, 절토량은 자연(Bank) 상태
- 성토에 필요한 자연토량 = `V_fill / C`. 토사 `C ≈ 0.88` 적용 시 **약 13.6% 과소**
- 결과적으로 유토 곡선이 실제보다 낙관적으로 그려져 **사토 과다·토취 누락 판단**을 유발

**조치**: `massHaulBank(i) = Σ(cutVol) − Σ(fillVol / C_layer)`로 교정하고, 곡선에 자유 운반거리
(Free Haul)와 초과 운반 구간을 음영으로 표기한다.

### D-03 [P0] 핸드오프가 측점 5개만 하류로 전달
`exportHandoff()`의 `sections_sample: APP_STATE.sections.slice(0, 5)` — 전 측점이 아니라 앞 5개만 실린다.
합계 물량(`total_cut_m3`/`total_fill_m3`)은 전량이므로, 하류가 측점별로 재검증할 방법이 없다.
연구자료 §6이 강조한 SSOT(단일 진실 공급원) 원칙과 정면 충돌한다.

**조치**: `sections_full[]` 전량 수록(측점 수 500 초과 시 gzip 대신 `sections_ref` 분리 파일 병행),
`sections_sample`은 미리보기 전용으로 명칭 변경.

### D-04 [P0] 좌표 합성이 “경고 문구”일 뿐 반출을 막지 않음
`coordSynthetic === true`여도 `exportLandXML()`·`exportBridgeCoordCSV()`·`genCoordScript()`는
경고 주석만 덧붙이고 **정상 반출**된다. 교각 좌표는 소수 3자리(mm)로 찍힌다.
연구자료 §4가 “파이프라인 진행을 차단하라”고 명시한 바로 그 지점이다.

**조치**: F-01의 하드 게이트로 승격. 합성 상태에서는 좌표 소비 산출물 3종을 `disabled`,
비좌표 산출물(물량 CSV 등)은 통과시켜 작업을 완전히 막지는 않는다.

### D-05 [P1] 지반유형이 측점마다 있는데 토량변화율은 전역 단일값
측점 레코드에 `gtype`(soil/ripping/blast)이 이미 있고 사면 구배도 유형별로 분리되어 있다.
그런데 `swell-factor`는 전역 입력 1개(기본 1.25)이며, 그마저 **공사비 계산에만** 곱해진다
(`costCut = totalCut × swell × cutUnit × coeff`). 물량·유토 계획에는 반영되지 않는다.

**조치**: `SWELL_REGISTRY = {soil:{L,C}, ripping:{L,C}, blast:{L,C}}`를 `KDS_CONSTANTS`와 같은
근거 필드 구조로 신설하고, `gtype`으로 자동 매핑. 전역 입력은 “일괄 덮어쓰기” 옵션으로 강등.

### D-06 [P1] 구조물 구간 물량이 0 — 접속부 토공 누락
`calcAllSections()`는 `if (s.stype === 'R')` 조건에서만 절·성토를 계산하고,
`calcVolumes()`도 `s1.stype==='R' && s2.stype==='R'`인 구간만 적산한다.
교대 뒤채움, 터널 갱구부 절취, 토공↔구조물 접속부(연구자료 §5.2의 트랜지션)가 전량 누락된다.

**조치**: 구조물 경계 전후 트랜지션 길이(기본 20 m, 조정 가능)를 정의하고 해당 구간을
`stype='X'`(전이)로 분류해 별도 산출. 동시에 F-05의 타겟 스위칭 스크립트와 구간 정의를 공유한다.

### D-07 [P1] 단가·타임스탬프 하드코딩
- `calcVolumes()` 내부 `var cutUnit = 8500, fillUnit = 12000;` — 출처·기준연도 없음.
  `KDS_CONSTANTS`가 모든 기준값에 `source`/`ref_doc`를 강제하는 앱 자체 원칙과 불일치.
- 전 내보내기 파일명이 `..._20260724_201932.{csv,json,xml,py}`로 **고정 문자열**.
  같은 날 여러 번 내보내면 파일이 서로 덮어쓰이고, 생성 시각을 파일명으로 추적할 수 없다.

**조치**: 단가를 `COST_REGISTRY`로 분리(`source: '건설공사 표준품셈/유사공사 실적' + 기준연도 필수 입력),
파일명은 `tsStamp()` 유틸로 실제 생성 시각 생성.

### D-08 [P2] 정확도·상호운용 세부
- **횡단경사 미반영**: `cross-slope` 입력이 단면적 계산에 들어가지 않는다(반폭 5 m·2% 기준 약 1.2% 편차).
- **LandXML 곡선 부재**: `exportLandXML()`이 측점 간을 전부 `<Line>`으로 잇는다. 실좌표를 받아도
  곡선은 현(弦) 근사가 되고, `<CrossSects>`·`<Surface>` 요소가 없어 횡단 정보가 실리지 않는다.
- **`runLawGate()`의 부수효과**: 게이트 실행이 `showStep(7)`로 화면을 강제 이동시킨다.
  API·심의 경로에서 호출될 때 사용자 맥락을 빼앗는다.

### F-02 [P0] 체적 기법 — 차단이 아니라 근거 기록 + 편차 경보 (v1.0 정정)
1. `vol-method`에 세 번째 선택지 **`prismoidal_curve`(각주공식 + 곡률 보정)** 추가
2. 양단면평균법 선택 시 **발주자 인정 근거 입력란을 필수화**(BIM 시행지침 2.4.2(2)).
   미입력이면 내보내기 차단 — 기법을 막는 게 아니라 **근거 없는 기법 선택**을 막는다
3. 세 기법을 항상 병렬 계산해 요약 카드에 병기하고, 편차 3% 초과 황색 / 7% 초과 적색 경보
4. **곡률 보정**: 실좌표가 있을 때 연속 3측점 외접원으로 `R`을 구하고, 단면 도심 편심 `e`에 대해
   `V' = V × (1 ± e/R)` 적용 (Pappus). 좌표가 합성이면 보정 자체를 비활성화하고 그 사실을 표기

```js
function radius3pt(a,b,c){                    // 외접원 반경 — 곡률 보정의 R
  var A=Math.hypot(b.e-a.e,b.n-a.n), B=Math.hypot(c.e-b.e,c.n-b.n), C=Math.hypot(c.e-a.e,c.n-a.n);
  var s=(A+B+C)/2, ar=Math.sqrt(Math.max(s*(s-A)*(s-B)*(s-C),0));
  return ar<1e-9 ? Infinity : (A*B*C)/(4*ar);  // 직선이면 Infinity → 보정계수 1
}
```
> Composite TIN은 앱에 표면(TIN) 데이터가 없어 **앱 내부 구현 대상이 아니다**. 대신 Civil 3D에서
> 산출한 복합토량 값을 역수입해 앱 산출값과 대조하는 **교차검증 카드**(§4)로 대체한다.

```js
  soil:    { L:1.25, C:0.88, source:'—', ref_doc:'프로젝트 토질조사 보고서', article:'입력 필요' },
  ripping: { L:1.35, C:1.02, source:'—', ref_doc:'프로젝트 토질조사 보고서', article:'입력 필요' },
  blast:   { L:1.55, C:1.18, source:'—', ref_doc:'프로젝트 토질조사 보고서', article:'입력 필요' }
};
```
> 기본값은 **착수용 참고치**다. `source`가 비어 있으면 산출물에 “기본계수 사용” 배지를 강제 부착하고,
> 근거 게이트에 **R05(토량변화율 출처 존재)** 를 추가해 미입력 상태를 가시화한다.

### F-05 [P1] 구조물 접속부 토공과 타겟 스위칭 — D-06 + 연구자료 §5.2
- 트랜지션 구간(`stype='X'`) 신설 → 접속부 토공 산출
- 동일 구간 정의를 `genCorridorScript()`에 주입해, 사면 타겟을 원지반 표면에서
  교대 벽면·갱구부 형상선으로 전환하는 코드를 자동 생성

### F-06 [P1] 게이트 차단력 부여 + R05~R08 신설
현행 `runLawGate()`는 판정만 하고 흐름을 막지 않는다. `blocking` 속성을 규칙에 추가한다.

| 규칙 | 검사 | 차단 |
|---|---|---|
| R05 | 토량변화율 출처 존재 | 경고 |
| R06 | 체적 산출 기법 근거 (AEA면 발주자 인정 기록) | **차단** |
| R07 | 좌표 실좌표 여부 | **좌표 소비 산출물만 차단** |
| R08 | 계획고 정의(포장상면/노상면) 선택 완료 | **차단** |

또한 `showStep(7)` 부수효과를 제거하고 호출자가 화면 이동을 결정하도록 바꾼다(D-08).

### F-07 [P1] 견고성 — 단가·타임스탬프·인코딩 (D-07 + 연구자료 §4)
- `COST_REGISTRY` 분리, 기준연도 필수
- `tsStamp()` 도입, 전 내보내기 파일명 동적 생성
- 생성 스크립트의 UTF-8 선언은 이미 있음(`# -*- coding: utf-8 -*-`) — 경로 인용과
  `chcp 65001` BAT 래퍼, 로컬 브리지 지수 백오프 재시도를 추가

### F-08 [P2] LandXML 곡선·횡단 보강 (D-08)
실좌표 + `R` 판정으로 `<Curve>` 요소를 생성하고, `<CrossSects>`에 측점별 단면 좌표열을 수록한다.
BIM 시행지침 발주자편 3.6.3이 LandXML을 IFC 대체 제출 포맷으로 인정하므로, 제출 성과품 품질에 직결된다.

### F-09 [P2] Civil 3D 복합토량 역수입 교차검증
Civil 3D에서 산출한 복합토량(Composite Volume) CSV를 앱에 다시 읽혀 앱 산출값과 구간별로 대조하고,
**편차 ±2% 초과 구간을 목록화**한다. 연구자료 §2.2의 평행 모델링을 앱 안에서 구현하는 방식이다.

### F-10 [P2] Revit Toposolid 서브디비전 스크립트 (연구자료 §5.1)
`SCRIPT_TEMPLATES`에 5번째 탭을 추가해 포장·길어깨·식수대 경계를 `Toposolid.CreateSubDivision()`으로
분할하는 템플릿을 제공한다. 경계 CurveLoop 유효성 검사와 실패 측점 로그를 포함한다.

## 6. 우선 착수 3건

1. **D-01 포장 두께 반영** — `calcCutArea`/`calcFillArea` 두 함수 수정으로 약 11%(기본값 기준) 물량 오차가 사라진다.
2. **D-02 유토곡선 상태 통일** — `drawMassHaul` 한 줄 수식 교정으로 사토·토취 판단이 뒤집힌다.
3. **D-03 핸드오프 전 측점 수록** — `slice(0,5)` 제거. 하류 앱이 비로소 측점별 검증을 할 수 있다.

세 건 모두 **함수 국소 수정**이며, 앱의 기존 구조(레지스트리·게이트·핸드오프 계약)를 그대로 활용한다.

**결론.** 이 앱은 이미 근거 레지스트리·게이트·핸드오프 계약·좌표 출처 추적을 갖춘 상위 수준의 도구다.
