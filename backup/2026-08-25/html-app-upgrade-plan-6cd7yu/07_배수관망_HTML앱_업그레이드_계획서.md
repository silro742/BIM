## 1. 계획 수립 원칙

이 계획은 연구 MD의 내용을 **앱의 기존 무결성 원칙과 충돌하지 않는 범위**에서 이식하는 것을 전제로 한다. 앱 v2.2.0이 확립한 다음 4가지 원칙은 모든 신규 기능에 그대로 적용한다.

1. **verified 플래그 원칙** — 조문 원문을 대조하지 못한 수치는 `verified:false`로 표기하고, 원문 미확보 기준은 `value:null` 슬롯으로 등재해 판정 시 FAIL이 아닌 **HOLD**를 낸다 (KDS_CONSTANTS · PRESSURE_CRITERIA 패턴).
2. **HOLD 강제 승격 금지** — HOLD를 PASS로 임의 변경하는 UI 경로를 만들지 않는다 (연구 MD §4.3).
3. **무효화(Invalidation) 원칙** — 기하 형상이 하나라도 변경되면 기존 판정 결과는 즉시 무효화한다 (연구 MD §3.1).
4. **단정 금지** — 합성 데이터·예시값 기반 산출은 설계 근거로 오독되지 않도록 화면·산출물 양쪽에 명시한다.

## 3. Phase 1 — v2.3.0 「입력 근거 강제판」 (우선순위 최상)

계산식 변경 없이 **입력의 근거와 판정의 기준면을 데이터로 남기는** 단계. 연구 MD가 지목한 치명적 설계 오류(§4.1·§4.2)와 시공성 실패 사례(§3.1·§3.2)의 직접 방어선이다. 기존 결과값이 바뀌지 않으므로 회귀 위험이 가장 낮다.

### P1-1. 유출계수 가중평균 산출기 (근거: MD §4.2)

- **문제**: 관경 축소 목적의 C 임의 삭감(어뷰징)을 막을 시스템 장치가 없다. 현재 C는 드롭다운 단일 선택이고 금지 문구만 있다.
- **구현**:
  - 수문 분석 탭에 「유출계수 산출 근거」 카드 신설. 행 = {표면 유형(포장/지붕/녹지/나지 등), 면적(ha), C값}. 가중평균 `C_w = Σ(Cᵢ·Aᵢ)/ΣAᵢ` 를 자동 산출해 C 입력에 반영.
  - 산출 근거(행 배열)를 `APP_STATE.hydro.c_basis`에 저장하고 Handoff JSON·자가 보고(app_report/v1)에 포함.
  - 가중평균을 쓰지 않고 C를 직접 고르면 `c_basis:{mode:'manual'}`로 기록 — **차단이 아니라 이력화**(직접 선택 자체는 정당한 실무이므로 금지하지 않되, 근거 없음이 산출물에 남게 한다).
  - 구성 면적 합계가 유역 면적 A와 ±5% 이상 어긋나면 경고.
- **검증**: 자기검증에 3항목 추가 — (a) 가중평균 계산 고정 벡터, (b) 면적 불일치 경고 도달, (c) c_basis가 자가 보고에 실리는지.
- **규모**: 소 (신규 카드 1 + 함수 2 + 스키마 필드 1)

### P1-2. IDF 교체 상태 추적 + 단위계 게이트 (근거: MD §4.1)

- **문제**: Talbot a/b 예시값(TALBOT_BY_T)을 실제 지역 IDF 회귀값으로 교체했는지 앱이 알지 못한다. 예시값 그대로 계산한 결과가 산출물에서 실측 기반 결과와 같은 얼굴을 한다.
- **구현**:
  - `APP_STATE.hydro.idf_source` 필드 신설: `'example'`(기본) | `'user'`. 사용자가 a/b 입력란을 직접 수정하거나 신규 「IDF 출처」 입력란(출처 문자열: 예 "OO지역 확률강우량도 2023 회귀")을 기입하면 `'user'`로 전환.
  - `idf_source==='example'` 상태로 유출량을 계산하면: 결과 카드에 자색 「예시값 계산」 배지, 자가 보고 summary에 `idf_source:'example'` 명기, **근거 게이트에 신규 G11(수문 입력 근거) 추가 — 예시값이면 HOLD**.
  - 재현기간 변경으로 a/b가 예시표에서 다시 대입되면 `'example'`로 복귀 (사용자 값을 조용히 덮지 않도록 대입 전 확인 문구).
  - 단위계: calcHyd() 진입 시 입력 자릿수 휴리스틱 경고 확장 — L(m)에 피트 의심값, S(%)에 무차원 의심값(예: S<0.05 입력) 감지 시 확인 요청. 이는 §4.1의 "리스너 단 1차 필터" 원칙을 자체 입력에도 적용하는 것.
- **검증**: 자기검증 3항목 — example→HOLD 도달, user 전환 후 PASS 가능, 재대입 시 example 복귀.
- **규모**: 소~중

### P1-3. 판정 결과 무효화(Invalidation) 일반화 (근거: MD §3.1 실패 사례)

- **문제**: 간섭 검사에는 invalidateClash()가 있으나, **룰셋 검증 결과 카드와 자가 보고**는 기하 변경 후에도 이전 결과가 화면에 그대로 남는다. 연구 MD의 광케이블 파손 사고(관경 1.5배 확대 후 구판 PASS 리포트 인용)와 동형의 위험.
- **구현**:
  - 공통 무효화 버스 `invalidateResults(reason)` 신설: 노드/관로/지장물/기준값 변경 시 → ① 간섭 결과(기존), ② 룰셋 검증 결과 카드에 「⚠ 형상 변경 후 미재검증」 오버레이, ③ `APP_STATE._lastOut`(마지막 내보내기 미리보기)에 stale 표식, ④ 자가 보고에 `geometry_rev`(기하 리비전 카운터) 포함.
  - 내보내기(JSON/LandXML/IFC/CSV/리포트) 실행 시 검증·간섭 결과가 stale이면 산출물 헤더/메타에 `validation_stale:true`를 명기 — 내보내기 자체는 막지 않는다(작업 중간 저장 용도 보존).
- **검증**: 자기검증 2항목 — 관경 변경 후 stale 플래그 set, 재검증 후 해제.
- **규모**: 중

### P1-4. 간섭표 판정 기준면 명기 (근거: MD §3.1 텍사스 성공 사례)

- **문제**: 간섭 계산은 3D 표면간 거리 기준으로 수행하지만, 결과 표에 **어느 기준면으로 판정했는지** 열이 없다. PUB 기준은 관경 600mm 이하 중심선 / 초과 외측으로 혼재해 있어 "실측값이 어느 면 기준인지" 오독 여지가 있다.
- **구현**:
  - 간섭 결과 표에 「판정 기준면」 열 추가: `표면간(외벽-외벽)` / `중심선(PUB≤600)` 등을 행별 명기.
  - PUB 모드에서 중심선 기준 행은 표면간 환산값을 괄호 병기해 현장 확보 가능 여유폭을 직관화.
  - QL 보수화가 적용된 행은 「실측 x.xx − QL여유 y.yy = 판정 z.zz」 형태로 감산 내역 병기 (현재는 최종값만 표시).
- **검증**: 자기검증 1항목 — PUB 600 이하/초과 각 1건의 기준면 라벨 고정 벡터.
- **규모**: 소

### P1-5. 피복 기준면(Reference Surface) 필드의 자체 상태 확장 (근거: MD §3.2)

- **문제**: pipe_network/v1 **수신** 시 cover_basis 미명기 → R3 HOLD는 구현되어 있으나, 앱 **자체 노드**의 지표고(sg)가 지표면인지 맨홀 림(rim)인지 구분하는 필드가 없고, 앱이 **내보내는** Handoff JSON에도 기준면 선언이 없다. 앱이 남에게 요구하는 계약을 스스로는 지키지 않는 비대칭.
- **구현**:
  - 노드에 `sg_basis` 필드 신설: `'ground'`(지표면, 기본) | `'rim'`(맨홀 상단) | `'unknown'`. 노드 표에 선택 열 추가.
  - `sg_basis:'unknown'` 노드가 물린 관로의 피복 판정은 R3 HOLD (FAIL 아님 — 기존 HOLD 패턴).
  - `sg_basis:'rim'`이면 피복 판정 결과에 「림 기준 — 지표면 피복과 상이할 수 있음」 병기.
  - Handoff JSON·app_report에 `cover_basis`·`network_ref_surface` 필드를 **발신 시에도** 포함 (수신 계약 승계조항 D와 대칭화).
- **검증**: 자기검증 2항목 — unknown→R3 HOLD 도달, 발신 페이로드 cover_basis 존재.
- **규모**: 중

### P1-6. 판정 결과 무결성 해시 강화 (근거: MD §4.3)

- **문제**: 자가 보고 checksum이 fnv1a(부동소수 곱 변형)로, 앱 스스로 "위변조 방지용이 아님"을 명기하고 있다. 연구 MD는 심의 결과가 타 시스템으로 전달될 때 변조 방지 해시를 요구한다.
- **구현**:
  - `crypto.subtle.digest('SHA-256', …)` 가용 시(Chrome file:// 포함 보안 컨텍스트) app_report에 `sha256` 필드 병기, 불가 환경은 `sha256:null` + 사유 명기. 기존 fnv1a checksum은 상호운용 하위호환으로 유지.
  - 해시 대상은 `{details, summary, geometry_rev, generated}` 직렬화 본문으로 고정하고 산정 규칙을 보고서 안에 자기 서술(어떤 키를 어떤 순서로 직렬화했는지) — 수신측 재검산 가능하게.
- **주의**: crypto.subtle은 비동기이므로 saveRpt()의 Promise 체인에 자연 편입. postMessage 회신 경로는 동기 유지 필요 시 fnv1a만 즉시 회신 + sha256 후속 회신.
- **검증**: 자기검증 1항목 — 고정 입력의 SHA-256 벡터 대조 (가용 환경에서만, 불가 시 SKIP 표기).
- **규모**: 소

**Phase 1 종합 규모**: 신규 UI 카드 2, 신규 게이트 1(G11), 스키마 필드 4, 자기검증 +12항목. 기존 계산 결과 불변 — 회귀 위험 낮음.

## 4. Phase 2 — v2.4.0 「수리 모델 확장판」

계산 엔진에 손을 대는 단계. 전 항목이 "원문 미확보 수치는 슬롯(null)로 등재하고 HOLD" 원칙을 따른다.

### P2-1. 침전물 두께 보정 부분흐름 (근거: MD §2.4 러시아 SP 32.13330.2018)

- **내용**: 룰셋 탭에 「침전물 예상 두께 h_sed(mm)」 선택 입력 신설(기본 미입력=미적용). 입력 시 부분흐름 판정에서 유효 수심을 `h_eff = h − h_sed`로 보정해 유속·통수능을 보수화.
- **구현**: partialFlow()를 건드리지 않고 래퍼 `partialFlowSed(Q,n,D,S,hsed)` 신설 — 침전 두께만큼 하부 단면을 제외한 원형관 부분단면(수치해)으로 계산. 침전 보정 적용 여부·값을 검증 결과와 산출물에 병기.
- **근거 처리**: SP 32.13330.2018 원문 미확보 — KDS_CONSTANTS 패턴으로 `sediment_allowance:{value:null, verified:false, ref_doc:'SP 32.13330.2018 — 원문 미확보'}` 슬롯 등재. **값 자체는 사용자 입력**(앱은 계수를 갖지 않음 — 동결심도 rfd와 동일 설계).
- **검증**: 자기검증 3항목 — h_sed=0이면 기존 partialFlow와 일치(회귀 앵커), h_sed>0이면 V 감소 방향 단조성, 침전 두께 ≥ 만관 수심이면 판정 불가 HOLD.
- **규모**: 중

### P2-2. 평균/첨두 유출계수(C_m/C_s) 이원 슬롯 (근거: MD §2.1 독일 DIN 1986-100)

- **내용**: 현재 "개념 병기만" 상태를 데이터 구조로 승격. 수문 탭에 C_s(첨두, 기존 C)·C_m(평균, 저류 체적용) 2필드로 분리하고, 합리식 Q는 C_s, SUDS 체적 환산은 C_m을 쓰도록 배선.
- **근거 처리**: DIN 1986-100 원문 미확보 유지 — C_m 미입력 시 기존 단일 C 동작 그대로(하위호환), 입력 시에만 이원 적용 + 「DIN 계열 이원화는 원문 미확보 — 개념 적용」 배지. 글로벌 비교표 DE 행의 서술과 일치화.
- **검증**: 자기검증 2항목 — C_m 미입력 시 기존 결과 불변(회귀 앵커), 입력 시 SUDS 체적만 변경.
- **규모**: 소

### P2-3. 과부하(Surcharge) 관로 리포트 (근거: MD §2.1 독일 Überstau 개념 차용)

- **내용**: DWA-A 118의 수리동역학 시뮬레이션은 도입하지 않되(§6-1), 그 **관리 개념**(초과 유량 관로의 식별·문서화)만 정적 계산 범위에서 차용. 검증 실행 시 `Q_설계/Q_full` 충전율 표 + 충전율≥100%(over) 관로 목록 + 하류 전파 표시(과부하 관로의 하류 경로 하이라이트)를 별도 카드로 출력.
- **주의 표기**: "정적 만관 대비 비율이며 DWA-A 118의 수리동역학 검증을 대체하지 않음 — 인허가용 범람 검토는 전용 프로그램 수행" 문구 고정 병기 (앱의 「하지 않는 것」 원칙과 정합).
- **규모**: 소 (기존 partialFlow의 over 플래그 집계 UI)

### P2-4. 내진 가요성 이음 속성 슬롯 (근거: MD §2.3 일본)

- **내용**: 관로에 `joint_type`('일반'|'가요성')·`joint_allow_disp_mm`(허용 변위, 선택) 속성 신설. 판정은 하지 않고(근거 기준 미확보) **속성 보존·핸드오프 전달**만 수행 — IFC/JSON 산출물에 실어 하류 구조 검토 도구가 쓰게 한다.
- **근거 처리**: `seismic_joint:{value:null, verified:false}` 슬롯 등재. 연약 지반·지진 지역 프로젝트에서 속성 미기입 시 근거 게이트에 정보성 표기(HOLD 아님 — 국내 필수 기준이 아니므로).
- **규모**: 소

**Phase 2 종합 규모**: 계산 래퍼 1, 스키마 필드 4, 자기검증 +6항목. P2-1은 회귀 앵커 테스트 필수.

## 5. Phase 3 — v2.5.0 「지형·산출물·자동화판」

기능 면적이 가장 큰 단계. 항목별 독립 배포 가능하도록 서로 결합하지 않는다.

### P3-1. 실지형 DEM 임포트 → 워터드롭 실좌표 승격 (근거: MD §1.2)

- **문제**: 워터드롭이 합성 지형 데모에 묶여 있어 "산출 좌표를 설계 근거로 사용 금지" 딱지를 뗄 수 없다. 연구 MD의 핵심 DNA(위상 기하학·공간 수문학 융합)에서 앱이 가장 크게 비는 지점.
- **구현**:
  - **ESRI ASCII Grid(.asc)** 파일 임포트 지원 (QGIS 4.0에서 `래스터 → 변환 → 포맷 변환`으로 DEM을 .asc로 내보내는 절차를 도움말에 병기). 텍스트 포맷이라 브라우저 FileReader만으로 파싱 가능 — 외부 라이브러리 불요(단일 HTML 원칙 유지).
  - 헤더(ncols/nrows/xllcorner/yllcorner/cellsize/NODATA_value) 파싱 → 격자 원점·셀 크기를 **파일에서 직접** 취득 (수동 입력 E0/N0와의 이중 관리 제거, 71.5km류 원점 오류 원천 차단).
  - 임포트 좌표가 현재 EPSG 노드 외접사각형과 1km 이상 이격 시 기존 checkWDOrigin() 경고 재사용.
  - traceWD()는 지형 배열 소스만 교체하면 재사용 가능(최급경사 추적은 동일). 격자 상한(예: 500×500)과 다운샘플 옵션으로 브라우저 메모리 보호.
  - **데모/실측 모드 분리**: 합성 지형 모드는 유지하되 결과 카드에 모드 배지. 실측 DEM 모드에서만 수렴점 좌표를 "집수정 후보(실좌표)"로 표기하고 Handoff JSON에 `terrain_source:{type:'esri_ascii', file, cellsize, crs_assumed}` 명기. NODATA 셀 유입 경로는 추적 중단 + 표기.
- **검증**: 자기검증 4항목 — 헤더 파싱 고정 벡터, NODATA 처리, 원점 이격 경고 도달, 합성 모드 회귀 앵커.
- **규모**: 대 (이번 계획 최대 항목 — 단독 릴리스 가치 있음)

### P3-2. IFC 4.3 Pset 확장 + IFC4 폴백 스위치 (근거: MD §5.3, §1.3)

- **내용**:
  - 내보내기 스텁에 관로별 `Pset_PipeSegmentTypeCommon` 속성값(내경·재질·조도계수 n·경사)과 커스텀 Pset(피복·QL 등급·검증 판정) 기입. 노드는 `Pset_DistributionChamberElementTypeCommon`.
  - **스키마 스위치** 신설: `IFC4X3_ADD2`(기본) | `IFC4(ISO 16739-1)` 폴백. IFC4 선택 시 IfcDistributionChamberElement 등 4.3 전용 클래스를 IFC4 호환 클래스(IfcDistributionFlowElement 등)로 강등 매핑하고 강등 내역을 파일 주석·화면에 보고.
  - BIM 설정 탭 체크리스트에 「발주처 IFC 4.3 수용 여부 **서면 승인** 확인」 항목 추가 (연구 MD §5.3의 착수 전 승인 절차) — 미확인 상태로 4.3 내보내기 시 정보성 경고.
- **근거 처리**: Pset 명칭·필수 속성은 buildingSMART 문서 대조 전 `verified:false` 병기 (기존 IFC 매핑 표의 주의 문구 승계).
- **규모**: 중

### P3-3. 5D 개략 물량 리포트 (근거: MD §2.1 영국 — 설계 초기 물량 연계)

- **내용**: 신규 내보내기 「물량 개산서」 — 관경·재질별 연장 집계, 맨홀/집수정 수량, 개략 터파기 체적(관별 `평균심도 × 터파기 폭(D_o + 여유폭×2) × 연장`, 여유폭은 사용자 입력·기본 0.3m), 되메우기·잔토 개략.
- **주의 표기**: "개산(Preliminary) — 법면 구배·터파기 안전 기준(굴착 심도별 구배) 미반영. 실시설계 물량은 횡단면 기반 산출로 대체" 명기. 산식 전부를 리포트 안에 병기(블랙박스 금지).
- **규모**: 중 (계산 단순, 표기 신중)

### P3-4. Dynamo 스크립트 생성기 2종 추가 (근거: MD §5.1)

- **① Revit 사이징 우회 스크립트**: 관망 위상 트리를 스캔해 수리적 최악 경로(Hydraulically Adverse Run)를 식별하고, 로컬 기준(KDS 61 계열 — 앱의 룰셋 탭 값을 스크립트에 주입)으로 산출한 관경·경사를 `Element.SetParameterByName`으로 강제 기입하는 PythonNet3 스크립트 생성. 앱에서 이미 계산한 관경 결과를 **데이터로 내장**한 스크립트를 뽑는 방식(스크립트가 재계산하지 않음 — 정본은 앱 계산).
- **② 지형 추종 배치 스크립트**: Civil 3D 지형 Z좌표 배열(CSV/리스트)을 읽어 관망 시스템 패밀리가 최소 피복(앱의 effMinCover() 결과값 주입)을 위반하지 않으며 지형을 따르도록 배치하는 스크립트 생성.
- **공통**: 기존 DYN_SCR 패턴 준수 — 문서 잠금을 트랜잭션보다 먼저, getattr 폴백, "사본에서 먼저 실행" 경고. 생성 스크립트에 앱 버전·기하 리비전(geometry_rev)·생성 시각 헤더 주입 (P1-3과 연동 — 구판 기하로 뽑은 스크립트 식별 가능).
- **규모**: 중 (템플릿 문자열 작업 위주)

## 7. 릴리스·검증 전략

### 7.1 버전·순서
- **v2.3.0 (Phase 1)** → **v2.4.0 (Phase 2)** → **v2.5.0 (Phase 3)**. P3-1(DEM)은 규모상 v2.5.0에서 분리해 v2.5.x 단독 릴리스 가능.

### 7.2 자기검증(런타임 단위 테스트) 확장

### 9.2 시뮬레이션으로 발견해 수정한 결함 3건

구현 중 헤드리스 시뮬레이션이 잡아낸, 코드만 봐서는 드러나지 않은 결함이다.

1. **해시 재검산 불일치** — `hash_spec`이 서술한 키 목록에 실제 해시 대상의 `ok` 필드가 빠져, 수신측이 서술대로 재구성한 해시가 어긋났다. 재검산 가능성이 P1-6의 존재 이유이므로, 해시 대상을 `SHA_KEYS` 배열 하나로 못박아 서술과 코드가 갈릴 수 없게 고쳤다.
2. **수신 관망의 기준면 이중 HOLD** — `pipe_network/v1` 수신 경로가 노드에 `sg_basis`를 심지 않아, 봉투가 `reference_surface`를 선언해도 노드는 `unknown`이 되어 R3가 이중으로 HOLD됐다(hybrid 자기검증 8/8→7/8 회귀로 검출). 봉투 어휘를 노드 어휘로 1:1 이식해 해소.
3. **퇴적 폐색 시 null 유속 예외** — 퇴적이 내경을 채우면 `pf.V`가 null인데 `runVal`이 `.toFixed`를 호출해 예외가 났다. 청관 만관유속으로 대체하면 「폐색인데 유속 정상」이라는 거짓 판정이 되므로, 유속을 **HOLD(판정 미성립)**로 두고 R2 게이트도 HOLD로 내리도록 고쳤다.
