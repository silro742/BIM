# .claude/agents — 팀원 역할 정의

## 왜 이 폴더가 필요한가

Claude Code의 **팀(Agent Teams)** 은 세션 하나에 종속됩니다. 공식 문서 기준:

- `One team per session` — 팀은 세션 1개에만 존재하며 세션 간 공유가 불가능하다
- 팀 설정 디렉터리(`~/.claude/teams/{team-name}/`)는 **세션이 끝나면 삭제**된다
- 팀 이름은 사람이 정하는 것이 아니라 `session-` + 세션 ID 앞 8자 로 자동 생성된다
- 팀·작업 디렉터리는 **로컬에만 저장되고 절대 업로드되지 않는다**

즉 "벼리팀"이라는 팀 자체는 원래부터 다음 세션으로 넘어갈 수 없는 구조입니다.
2026-06-24 까지 쓰시던 팀이 사라진 것은 고장이 아니라 이 설계 때문입니다.

**대신 남길 수 있는 것이 팀원의 역할 정의입니다.**
이 폴더에 정의를 두면 팀은 매번 새로 만들어지더라도 **같은 역할의 팀원을 언제든 재소환**할 수 있고,
저장소에 커밋되므로 로컬 PC든 클라우드 세션이든 따라옵니다.

## 사용법

정의를 만든 뒤 이렇게 말하면 그 역할로 팀원이 뜹니다.

    벼리 에이전트 타입으로 팀원을 띄워서 06 표준횡단 앱을 검토해줘

## 파일 형식

파일 하나가 역할 하나입니다. 맨 위 `---` 블록이 설정, 그 아래가 그 팀원에게 주는 지시문입니다.

    ---
    name: 벼리
    description: 언제 이 역할을 쓰는지 한 줄로. Claude가 이 문장을 보고 선택합니다.
    tools: Read, Grep, Glob, Bash
    model: opus
    ---

    (여기에 그 팀원이 항상 지켜야 할 규칙과 작업 방식을 씁니다)

| 항목 | 설명 |
|---|---|
| `name` | 소환할 때 부르는 이름. 파일명과 맞추세요 |
| `description` | 필수. 이 역할을 언제 쓰는지 |
| `tools` | 생략하면 전체 도구 사용. 조사 전용이면 `Read, Grep, Glob, WebSearch, WebFetch` 로 제한 권장 |
| `model` | `opus` / `sonnet` / `haiku`. 생략하면 팀장 모델을 따름 |

## 주의

- `skills` 와 `mcpServers` 항목은 팀원으로 실행될 때 적용되지 않습니다
- 정의 본문은 기본 시스템 프롬프트를 **대체하지 않고 뒤에 덧붙습니다**
- `.claude/teams/` 를 직접 만들어도 인식되지 않습니다. 역할 정의는 반드시 이 폴더에 둡니다

## 현재 상태

`_템플릿.md` 만 들어 있습니다.

`tools/01_진단_벼리팀찾기.ps1` 을 PC에서 실행해 나온 결과로 복원합니다.
