# 클로드 코드 사용 가이드 초보자용

## 1. 시작하기 전에

### 지금 무슨 일이 있었나
  - 2026년 6월까지 로컬 PC에서 클로드와 작업했다
  - 8월에 작업 환경이 깃허브 기반으로 바뀌었다
  - 그 뒤 벼리팀과 앱성팀이 보이지 않게 되었다
  - 원인은 팀 기능이 꺼져 있었고 로컬 자료가 깃허브에 없었기 때문이다
  - 로컬 PC 파일은 지워지지 않았다

### 원인 세 가지

| 원인 | 내용 | 해결 |
|---|---|---|
| 팀 기능 꺼짐 | 클라우드 세션에서 기본값이 비활성 | 설정 파일에 플래그 추가 |
| 팀의 구조 | 팀은 세션 종료와 함께 사라지는 설계 | 역할을 파일로 저장 |
| 저장소가 비어 있음 | 깃허브에 HTML 한 개뿐이었음 | 로컬 전체를 올림 |

### 앞으로 어떻게 되나
  - 작업은 로컬 PC 토성 폴더에서 한다
  - 결과는 깃허브에 자동으로 보관한다
  - 팀 기능을 다시 켠다
  - 같은 일이 다시 생기지 않는다

### 알아둘 용어

| 용어 | 뜻 |
|---|---|
| 로컬 PC | 지금 쓰는 내 컴퓨터 |
| 클라우드 | 인터넷 저쪽의 임시 컴퓨터 |
| 깃허브 | 파일을 보관하고 이력을 남기는 곳 |
| 저장소 | 깃허브에 있는 내 프로젝트 공간 |
| 커밋 | 현재 상태를 하나의 기록으로 남기는 일 |
| 푸시 | 그 기록을 깃허브로 올리는 일 |
| 브랜치 | 작업 갈래 |
| 터미널 | 명령어를 입력하는 검은 창 |
| 세션 | 클로드를 켜서 끌 때까지의 한 번의 대화 |

### 세 가지 저장 위치

| 위치 | 용도 | 클로드를 껐다 켜면 |
|---|---|---|
| 토성 폴더 | 실제 작업하는 곳 | 그대로 남음 |
| 깃허브 | 백업과 이력 보관소 | 그대로 남음 |
| 클라우드 세션 | 임시 작업장 | 사라짐 |

  - 그래서 클라우드에서 만든 것은 반드시 푸시해야 한다

## 2. 준비 작업

### 파워셸 여는 법
  - 키보드에서 윈도우 키를 누른다
  - powershell 이라고 입력한다
  - Windows PowerShell 을 클릭한다
  - 파란 창이나 검은 창이 열리면 성공이다
  - 창 왼쪽에 PS C 로 시작하는 글자가 보인다

### 스크립트 파일 네 개

| 번호 | 파일 | 무엇을 하는가 | 안전한가 | 언제 |
|---|---|---|---|---|
| 01 | 진단_벼리팀찾기 | PC에서 팀 흔적을 찾음 | 읽기만 함 | 처음 한 번 |
| 02 | 로컬복귀_설치 | 클로드 설치와 팀 기능 켜기 | 기존 설정 백업 후 추가 | 처음 한 번 |
| 03 | 토성_깃허브_연결 | 폴더를 저장소에 연결 | 파일 안 건드림 | 04가 자동 실행 |
| 04 | 로컬을_깃허브에_반영 | 로컬 내용을 깃허브에 올림 | 확인 후 진행 | 처음 한 번 |

  - 받은 파일 네 개를 한 폴더에 모은다
  - 바탕화면에 스크립트 라는 폴더를 만들어 넣으면 편하다

### 그 폴더로 이동하는 법
  - 파워셸에 cd 를 입력하고 한 칸 띄운다
  - 폴더를 파워셸 창으로 끌어다 놓는다
  - 경로가 자동으로 입력된다
  - 엔터를 누른다

### 명령 입력 규칙

| 하고 싶은 것 | 방법 |
|---|---|
| 명령 실행 | 한 줄 입력 후 엔터 |
| 붙여넣기 | 마우스 오른쪽 클릭 |
| 이전 명령 다시 쓰기 | 위쪽 화살표 |
| 실행 중단 | 컨트롤 키와 C |
| 대소문자 | 구분하지 않음 |

## 3. 첫 번째 단계 설치하기

### 무엇을 하는가
  - 클로드 코드 프로그램을 PC에 설치한다
  - 팀 기능을 켜는 설정을 넣는다
  - 이미 설치되어 있으면 설정만 손댄다

### 실행 명령
  - powershell -ExecutionPolicy Bypass -File .\02_로컬복귀_설치.ps1

### 화면 진행 순서

| 단계 | 화면에 나오는 것 | 할 일 |
|---|---|---|
| 1 3 | 클로드 코드 설치 확인 | 없으면 진행할까요 묻는다 |
| 확인 | 진행할까요 Y N | Y 입력 후 엔터 |
| 설치 | 몇 분 걸림 | 기다린다 |
| 2 3 | 설정 파일 백업과 수정 | 자동 |
| 3 3 | 검증 결과 | 초록색 OK 확인 |

### 잘 되었는지 확인하는 법
  - 초록색 글씨 OK 가 여러 줄 보이면 성공이다
  - 파워셸 창을 닫았다가 다시 연다
  - claude --version 을 입력한다
  - 숫자로 된 버전이 나오면 설치된 것이다

### 이 단계가 안전한 이유
  - 기존 설정 파일을 먼저 백업한다
  - 백업 파일 이름 끝에 날짜와 시각이 붙는다
  - 기존 설정을 지우지 않고 항목만 더한다

## 4. 두 번째 단계 진단하기

### 무엇을 하는가
  - 벼리팀과 앱성팀의 흔적을 PC 전체에서 찾는다
  - 결과를 바탕화면에 보고서로 저장한다
  - 읽기만 하므로 몇 번을 실행해도 상관없다

### 실행 명령
  - powershell -ExecutionPolicy Bypass -File .\01_진단_벼리팀찾기.ps1

### 검사 항목 여덟 개

| 번호 | 검사 대상 | 무엇을 알 수 있나 |
|---|---|---|
| 1 | 실행 환경 | 클로드가 설치되어 있는지 |
| 2 | 설정 파일 | 팀 기능이 켜져 있는지 |
| 3 | agents 폴더 | 팀원 역할 정의가 남아 있는지 |
| 4 | teams 폴더 | 팀 설정 잔여물 |
| 5 | tasks 폴더 | 팀의 작업 목록이 남아 있는지 |
| 6 | projects 폴더 | 지난 대화 기록 |
| 7 | 토성 폴더 | 앱 파일 목록과 버전 |
| 8 | 바탕화면 전체 | 이름에 벼리 앱성이 든 파일 |

### 결과 확인하는 법
  - 바탕화면에 벼리팀_진단결과 로 시작하는 txt 파일이 생긴다
  - 그 파일을 더블클릭해서 연다
  - 내용을 전체 선택해 복사한다
  - 클로드에게 붙여넣어 준다

### 결과가 뜻하는 것

| 결과 | 뜻 | 다음 조치 |
|---|---|---|
| 3번에 파일 있음 | 역할 정의가 살아 있음 | 그 내용을 클로드에게 전달 |
| 5번에 6월 폴더 있음 | 팀 작업 내용이 남아 있음 | 폴더 내용을 전달 |
| 6번에 기록 있음 | 지난 대화가 남아 있음 | 파일 경로를 전달 |
| 모두 없음 | 팀이 세션과 함께 사라짐 | 역할을 새로 만들면 됨 |

  - 모두 없음이어도 문제가 아니다

## 5. 세 번째 단계 깃허브에 올리기

### 무엇을 하는가
  - 토성 폴더 내용을 깃허브에 전부 올린다
  - 깃허브 내용을 로컬과 똑같이 만든다
  - 앞으로 백업이 자동으로 쌓이기 시작한다

### 실행 명령
  - powershell -ExecutionPolicy Bypass -File .\04_로컬을_깃허브에_반영.ps1

### 실행 전에 알아둘 것
  - 로컬 토성 폴더가 원본이 된다
  - 깃허브에 있던 예전 내용은 참고하지 않는다
  - 다만 예전 기록은 이력에 남아 되돌릴 수 있다
  - 03번 연결은 04번이 자동으로 처리한다

### 화면 진행 순서

| 단계 | 하는 일 | 사용자가 할 것 |
|---|---|---|
| 1 6 | 폴더 확인과 저장소 연결 | 인증 창 뜨면 로그인 |
| 2 6 | 큰 파일 검사 | 경고 나오면 확인 |
| 3 6 | 팀 기능 설정 파일 생성 | 없음 |
| 4 6 | 무엇이 바뀌는지 목록 표시 | 삭제 목록 확인 |
| 5 6 | 진행할까요 질문 | Y 또는 N |
| 6 6 | 커밋과 푸시 | 기다린다 |

### 확인 화면 색상 읽는 법

| 색 | 표시 | 뜻 |
|---|---|---|
| 초록 | 추가 | 새로 올라갈 파일 |
| 노랑 | 수정 | 내용이 바뀔 파일 |
| 빨강 | 삭제 | 깃허브에서 없어질 파일 |

  - 빨강 목록을 눈으로 한 번 확인한다
  - 문제 없으면 Y 를 입력하고 엔터를 누른다
  - 이상하면 N 을 입력하면 아무 일도 일어나지 않는다
  - 삭제된 파일도 이력에 남아 되돌릴 수 있다

### 잘 되었는지 확인하는 법
  - 마지막에 완료 라는 글자가 나온다
  - 브라우저에서 github.com/silro742/BIM 을 연다
  - 토성 폴더와 같은 파일들이 보이면 성공이다

### 실패했을 때

| 증상 | 원인 | 해결 |
|---|---|---|
| 인증 창이 반복됨 | 로그인 안 됨 | 깃허브 계정으로 로그인 |
| 파일이 크다고 나옴 | 100MB 초과 | 그 파일을 폴더 밖으로 |
| 네트워크 오류 | 연결 불안정 | 자동으로 네 번 재시도함 |
| 그 밖의 오류 | 확인 필요 | 화면 내용을 클로드에게 전달 |

## 6. 매일 쓰는 방법

### 작업 시작할 때
  - 파워셸을 연다
  - cd "$env:USERPROFILE\Desktop\토성" 을 입력한다
  - claude 를 입력한다
  - 클로드가 준비되면 그냥 한국어로 말하면 된다

### 작업 끝낼 때
  - 커밋하고 푸시해줘 라고 말한다
  - 이 한 마디가 백업이다
  - 하루에 여러 번 해도 좋다

### 이것만 지키면 되는 원칙

| 원칙 | 이유 |
|---|---|
| 작업은 로컬에서 | 파일 전체 접근과 앱 실행이 가능 |
| 결과는 깃허브에 | 올리지 않은 것은 없어질 수 있음 |
| 자주 커밋 | 되돌릴 지점이 많아짐 |

### 클로드 끝내는 법
  - exit 를 입력한다
  - 또는 컨트롤 키와 C 를 두 번 누른다

## 7. 클로드에게 말하는 방법

### 기본 원칙
  - 한국어로 평소처럼 말하면 된다
  - 명령어를 외울 필요가 없다
  - 파일 이름을 정확히 몰라도 된다

### 이렇게 말하면 된다

| 하고 싶은 일 | 이렇게 말한다 |
|---|---|
| 파일 내용 파악 | 06 표준횡단 앱에 무슨 기능이 있는지 알려줘 |
| 오류 찾기 | 07 배수 앱에서 계산이 틀린 부분을 찾아줘 |
| 폴더 정리 | 토성 폴더에 뭐가 들어있는지 정리해줘 |
| 백업 | 커밋하고 푸시해줘 |
| 변경 확인 | 지금까지 바뀐 내용을 보여줘 |
| 되돌리기 | 어제 상태로 되돌려줘 |
| 별도 갈래 | 새 브랜치를 만들어서 거기에 올려줘 |
| 검토 | 이 앱에서 오류가 날 만한 곳을 찾아줘 |
| 근거 확인 | 법령 근거가 맞는지 확인해줘 |

### 잘 말하는 요령
  - 무엇을 원하는지 먼저 말한다
  - 어느 파일인지 알려주면 더 정확하다
  - 하지 말아야 할 것도 같이 말하면 좋다
  - 결과 형식을 정해주면 그대로 만든다
  - 확인 안 되는 것은 확인 불가로 표시해줘 라고 덧붙이면 좋다

## 8. 팀 기능 사용하기

### 팀이 무엇인가
  - 여러 클로드가 동시에 다른 일을 맡는 것이다
  - 각자 따로 생각하고 서로 대화한다
  - 벼리팀 앱성팀이 이 기능이었다

### 팀을 부르는 법
  - 팀원 세 명을 띄워서 06 앱을 각각 다른 관점으로 검토해줘
  - 이렇게 말하면 클로드가 알아서 팀을 만든다

### 팀원 다루는 법

| 하고 싶은 것 | 방법 |
|---|---|
| 팀원 고르기 | 위아래 화살표 |
| 팀원 화면 보기 | 엔터 |
| 팀원에게 직접 말하기 | 엔터로 들어간 뒤 입력 |
| 팀원 멈추기 | x 키 |
| 작업 목록 보기 | 컨트롤 키와 T |

### 팀에 대해 알아야 할 사실

| 사실 | 뜻 |
|---|---|
| 팀은 세션 하나에만 존재 | 다른 세션에서 부를 수 없음 |
| 클로드를 끄면 사라짐 | 고장이 아니라 원래 구조 |
| 작업 목록은 로컬에만 남음 | 깃허브에 올라가지 않음 |
| 이름은 자동 생성 | 사람이 고정할 수 없음 |

  - 벼리팀이 사라진 것도 이 때문이다

### 팀을 매번 되살리는 법
  - 역할을 파일로 만들어 두면 된다
  - 토성 폴더 안 .claude 폴더 안 agents 폴더에 넣는다
  - 벼리.md 같은 이름으로 저장한다
  - 다음부터 벼리 타입으로 팀원을 띄워줘 라고 하면 된다
  - 이 파일은 깃허브에 올라가므로 없어지지 않는다

### 역할 파일 만드는 법
  - 클로드에게 벼리팀 역할 파일을 만들어줘 라고 말한다
  - 어떤 일을 시키고 싶은지 설명한다
  - 클로드가 형식에 맞게 만들어 준다

## 9. 자주 생기는 문제

### 증상별 해결법

| 증상 | 원인 | 해결 |
|---|---|---|
| claude 를 찾을 수 없음 | 경로가 아직 반영 안 됨 | 파워셸 창을 닫고 다시 연다 |
| 스크립트 실행이 막힘 | 실행 정책 제한 | 명령 앞에 ExecutionPolicy Bypass 를 붙인다 |
| 한글이 깨져 보임 | 글꼴 문제 | 창 속성에서 굴림체나 D2Coding 으로 변경 |
| 인증 창이 계속 뜸 | 첫 로그인 필요 | 한 번 로그인하면 다시 묻지 않음 |
| 파일이 너무 큼 | 100MB 초과 | 그 파일을 토성 폴더 밖으로 옮김 |
| 실수로 파일 삭제 | 깃허브에 올린 뒤라면 복구 가능 | 어제 상태로 되돌려줘 |
| 팀원이 안 보임 | 유휴 상태로 숨겨짐 | 이름을 불러 메시지를 보냄 |
| 무엇을 할지 모름 | 상황 불명확 | 화면 글자를 그대로 클로드에게 전달 |

### 도움 요청할 때 알려줄 것
  - 어떤 명령을 실행했는지
  - 화면에 나온 글자 전체
  - 무엇을 하려던 중이었는지

## 10. 하지 말아야 할 것

### 위험한 행동

| 하지 말 것 | 이유 | 대신 |
|---|---|---|
| 브랜치 함부로 삭제 | 그 이력이 함께 사라짐 | 통합 확인 후에만 삭제 |
| .git 폴더 손으로 삭제 | 연결과 이력이 끊김 | 클로드에게 물어본다 |
| 모르는 명령 붙여넣기 | 결과를 예측할 수 없음 | 무슨 뜻인지 먼저 묻는다 |
| 며칠씩 커밋 안 함 | 되돌릴 지점이 없음 | 작업 단위마다 커밋 |
| 같은 파일 여러 곳 복사 | 어느 것이 최신인지 모름 | 한 곳만 원본으로 |
| 버전 번호 임의 변경 | 이력 추적이 어려움 | 규칙대로 올림 |

### 클라우드 세션에서 주의할 것
  - 클라우드는 깃허브에 올린 것만 볼 수 있다
  - 클라우드에서 만든 것은 푸시해야 남는다
  - 로컬 파일은 클라우드에서 보이지 않는다
