## 0. 요약 (Executive Summary)

연구자료는 6개 장에 걸쳐 표준횡단·횡단토공 파이프라인의 기술 DNA, 8개 권역 실무 사례, 시공성 검토, 치명적 설계 오류, 히든 팁, 통합 인사이트를 다룬다. 이를 **단일 파일 HTML 앱이 실제로 수행할 수 있는 작업 단위**로 환원하면 다음 4개의 축으로 수렴한다.

| 축 | 연구자료 근거 | 앱에서의 구현 형태 | 우선순위 |
|---|---|---|---|
| **A. 무결성 게이트 강화** | §4 좌표 합성 왜곡, 코리더 타겟 단절, 인코딩 파손 | 진입 차단형 검증 엔진 `G0~G6` | **P0 (최우선)** |
| **B. 체적 산출 정확도** | §3 양단면평균법 vs 복합토량법, 토량변화율 | 브라우저 내 프리즘 적분 + L/C 계수 엔진 | **P0** |
| **C. 하류 자동화 산출물 고도화** | §5.1 Toposolid 서브디비전, §5.2 타겟 스위칭, §2.3 가상 분할 | 스크립트 생성기 v2 + 4D/5D 속성 주입 | **P1** |
| **D. 데이터 유통 표준화** | §6 SSOT, IFC 4.3 / LandXML | 표준 스키마 v2 + 내보내기 계층 | **P1** |

> **핵심 판단**: 연구자료가 지적한 실패의 대부분은 *계산 정밀도*가 아니라 **데이터 무결성 붕괴**에서 발생한다(좌표 합성, 타겟 단절, 인코딩 파손). 따라서 본 업그레이드는 "기능 추가"보다 **"통과시키지 않는 게이트키퍼"의 강화**를 1순위로 둔다. Node 06의 존재 이유가 게이트키퍼이기 때문이다.

## 1. 연구자료 정밀 분석 → 적용 후보 도출

### 1.1 §1 기술적 핵심 DNA

| 연구자료 내용 | 앱 적용 가능성 | 판정 |
|---|---|---|
| .NET 8 기반 동적 재구성(Rebuild) | 앱은 Civil 3D를 직접 제어하지 않음. 다만 **"재구성 여부"를 검증**하고, 스크립트로 `Rebuild` 강제 삽입은 가능 | **부분 적용 (F-05)** |

| MCP 기반 공간 검증 · AI 어시스턴트 | 오프라인 단일 HTML에서 LLM 호출은 부적합. **룰 기반 검토 어시스턴트**로 치환 | **대체 적용 (F-13)** |
| HRA(수평선형 회귀분석), 포인트클라우드 노이즈 제거 | 브라우저에서 **RANSAC 기반 직선/원 피팅**으로 측점 표고·좌표 이상치 탐지는 충분히 구현 가능 | **축소 적용 (F-12)** |

### 1.3 §3 시공성 검토 → 계산 엔진 요구사항

연구자료가 제시한 3개 산출법의 특성을 앱 구현 관점으로 재정리한다.

| 산출법 | 오차 특성 | 앱 구현 난이도 | 채택 |
|---|---|---|---|
| 양단면평균법 (Average End Area) | 급곡선·교차로에서 편심 미반영 → 수만 m³ 오차 사례 | 낮음 (이미 구현 가능) | **참조용으로만 유지, 단독 사용 시 경고** |
| 정밀법 (Prismoidal) | 중앙단면 가중평균, TIN 불규칙성 미반영 | 중간 | **보조 지표로 병기** |
| 복합토량 / TIN 프리즘 적분 | 최상위 정확도, 지형 굴곡 반영 | 높음(브라우저 연산) | **기본값으로 채택 (F-02)** |

**추가 도출 요구사항**: 연구자료 §3 후반부의 *토량 변화율(Shrinkage & Swell)* 미반영 문제 → 순수 기하 체적만 하류로 보내면 사토장 용량 초과·공정 지연 발생. 따라서 **기하체적(Geometric Volume)과 시공체적(Bank/Loose/Compacted)을 반드시 분리하여 출력**해야 한다.

### 1.4 §4 치명적 설계 오류 → 게이트 사양

| 오류 | 탐지 신호 | 게이트 동작 |
|---|---|---|
| 좌표 합성(Synthesized) 왜곡 | 비고란 `좌표합성` 태그, EPSG 누락, 원점 (0,0), 곡선 구간의 방위각 변화율 0 | **G1: HARD BLOCK** (파이프라인 진행 차단, 상류 재발행 요구) |
| 코리더 타겟 단절 | 측점별 좌/우 daylight 타겟 `none` 연속 구간, rebuild 타임스탬프 < 선형 수정 타임스탬프 | **G3: BLOCK / WARN** |
| 자동 재구성 OFF 상태 성과품 추출 | `corridor.autoRebuild=false` + 캐시 해시 불일치 | **G3: WARN + 강제 Rebuild 스크립트 발행** |
| 인코딩 파손·경로 공백 | 생성 스크립트 내 non-ASCII 리터럴, 경로에 공백/한글, BOM 유무 | **G5: 생성 시점 자동 교정 + 리포트** |
| 콜드 스타트 연결 거부 | 로컬 HTTP 포트 미응답 | **G6: 헬스체크 폴링 + 지수 백오프 코드 자동 삽입** |

### 1.5 §5 히든 팁 → 스크립트 생성기 확장

- **§5.1 Toposolid.CreateSubDivision()**: 코리더 링크/형상선 외곽선 → JSON → Revit API로 포장층·길어깨·식수대 논리 분할 및 재질 자동 부여. → **F-09 (Revit 생성기 신규 템플릿)**
- **§5.2 구조물 구간 타겟 스위칭**: 측점 메타데이터 `stype = B(교량)/T(터널)/E(토공)` 감지 → 비탈면 타겟을 지표면 → 구조물 형상선으로 자동 전환. → **F-05 (Dynamo 생성기 신규 템플릿)**
- **§5.3 MMS 성능 최적화**: 작업 중 Surface LOD 낮춤 → 내보내기 시 High-fidelity 자동 갱신 루틴 삽입. → **F-14 (성능 프로파일 + 스크립트 후처리 루틴)**

## 2. 현행 앱 구조 진단 및 갭 분석

동일 계열 앱(`BIM_Slope_EL_Automation.html`, 962행)의 아키텍처를 기준으로 Node 06의 구조를 다음과 같이 상정하고 갭을 정리한다.

```
[현행 구조 - 상정]
 ┌────────────────────────────────────────────────────────┐
 │ 단일 HTML (인라인 CSS + 인라인 JS, 빌드 없음, 오프라인)      │
 │  ├ Step Nav (좌측)                                       │
 │  ├ Canvas 2D 뷰어                                         │
 │  ├ 전역 상태 변수 (let surface, activeStep, ...)          │
 │  ├ 도메인 엔진 (TIN/기하 클래스)                            │
 │  ├ 규정 데이터 상수 (REGULATIONS[])                        │
 │  └ SCRIPT_TEMPLATES{ dynamo, revit_csharp, civil3d_* }   │
 └────────────────────────────────────────────────────────┘
```

| 영역 | 현행 수준(상정) | 목표 수준 | 갭 |
|---|---|---|---|
| 입력 검증 | 형식 검사 위주 | **공간·기하·의미 3단 검증** | 좌표계/곡률/체인 무결성 검증 부재 |
| 체적 산출 | 양단면평균 중심 | 복합토량(프리즘 적분) 기본 | 적분 엔진, 토량변화율 엔진 부재 |
| 상태 관리 | 전역 `let` 변수 산재 | 단일 스토어 + 불변 스냅샷 | 되돌리기/재현성 불가 |
| 산출물 | 스크립트 코드 문자열 | 스크립트 + LandXML + CSV + 검증리포트 | 표준 포맷 부재 |
| 성능 | 전체 재렌더 | Web Worker + 증분 렌더 | 수천 측점 시 UI 정지 |
| 신뢰성 | 예외 처리 부분적 | 게이트별 상태머신 + 감사로그 | 실패 원인 추적 불가 |

### 3.3 게이트 엔진 사양 (G0 ~ G6)

| ID | 게이트명 | 검사 항목 | 실패 시 |
|---|---|---|---|
| **G0** | 스키마 정합 | 필수 필드, 타입, 단위, 측점 정렬·중복 | BLOCK |
| **G1** | 좌표계 무결성 | ① `epsg` 존재 및 화이트리스트(5185/5186/5187/5179/32652) ② 원점 (0,0) 금지 ③ 좌표 범위 sanity (중부원점: E 130k~270k, N 400k~800k) ④ `remark`에 `좌표합성`/`SYNTHESIZED` 태그 ⑤ 곡선 구간인데 방위각 변화율 ≈ 0 (합성 직선 탐지) ⑥ 측점 간 실거리 vs 측점차 편차 > 0.05 m | **HARD BLOCK** |
| **G2** | 선형 기하 | 클로소이드 `A² = R·L` 검증, 곡률 연속성, 완화곡선 최소길이, 측점 방정식 반영 | BLOCK/WARN |
| **G3** | 코리더 타겟 | 타겟 `none` 연속구간 길이, 구조물 구간(B/T)에서 surface 타겟 잔존, `lastRebuildAt < alignmentModifiedAt` (stale), `autoRebuild=false` | BLOCK/WARN |
| **G4** | 표준횡단 규정 | 차로폭·횡단경사·비탈면 구배·소단 간격의 설계기준 범위, 편경사 접속설치 구간 정합 | WARN |
| **G5** | 인코딩·경로 | 생성 스크립트의 non-ASCII 리터럴, 경로 공백/한글, 개행(CRLF/LF), 파일 인코딩 | **자동 교정** |
| **G6** | 통신 프로토콜 | 로컬 HTTP 포트 점유, 콜드스타트 헬스체크, 타임아웃 | **자동 교정** |

**게이트 상태머신**

```
IDLE ──load──▶ VALIDATING ──all pass──▶ READY ──emit──▶ EMITTED
                   │
                   ├── WARN ──user ack──▶ READY(⚠ 리포트에 잔류)
                   └── BLOCK ──────────▶ SEALED  (하류 산출 버튼 전면 비활성)
```

> `SEALED` 상태에서는 스크립트 생성·다운로드·클립보드 복사 버튼이 **모두 비활성화**된다. 연구자료 §4의 "잘못 합성된 데이터가 LandXML/CSV를 통해 Revit 구조물 배치 스크립트로 흘러 들어가는" 최악 시나리오를 물리적으로 차단하기 위함이다.

const KOREA_CRS = {
  5185:{name:'서부원점 2010', fe:200000, fn:600000, lon0:125},

function gateG1(data){
  const f=[]; const crs=data.project?.crs;

for each 선형요소 e where e.type ∈ {arc, clothoid}:

### F-02 · 복합토량(TIN 프리즘 적분) 산출 엔진 (P0)

**근거** 연구자료 §3 전체

**3-Way 병렬 산출**: 동일 구간에 대해 세 방식을 모두 계산해 **오차를 가시화**한다(독일 평행 모델링 기법의 응용).

| 방식 | 산식 |
|---|---|
| 양단면평균법 | `V = (A₁ + A₂)/2 × L` |
| 정밀법(Prismoidal) | `V = L/6 × (A₁ + 4A_m + A₂)` |
| 곡선보정 양단면 | `V = (A₁+A₂)/2 × L × (1 ∓ e/R)` — Pappus 중심법, `e`=단면 도심 편심 |
| **복합토량(기본값)** | EG·DG TIN을 격자로 샘플링해 프리즘 적분 |

**프리즘 적분 구현 (브라우저 실행 가능형)**

```js
// 격자 샘플링 적분 — 격자 간격 g(기본 0.5m), Web Worker에서 실행
function compositeVolume(egTIN, dgTIN, boundary, g=0.5){
  const bb = bboxOf(boundary);
  let cut=0, fill=0, cells=0;
  for(let x=bb.minX+g/2; x<bb.maxX; x+=g){
    for(let y=bb.minY+g/2; y<bb.maxY; y+=g){
      if(!pointInPolygon(x,y,boundary)) continue;
      const ze=egTIN.getElevation(x,y), zd=dgTIN.getElevation(x,y);
      if(ze==null||zd==null) continue;
      const d = ze - zd;                 // +: 절토, -: 성토
      if(d>0) cut += d*g*g; else fill += -d*g*g;
      cells++;
    }
  }
  return {cut, fill, net:cut-fill, cells, gridSize:g,
          method:'composite-tin-prism',
          convergence: null};            // 격자 수렴 검증은 아래 참조
}
```

**격자 수렴 검증(정직성 장치)**: `g = 1.0 → 0.5 → 0.25`로 3회 계산하여 체적 변화율이 0.5% 이내로 수렴할 때만 "확정" 배지를 부여하고, 수렴하지 않으면 "미수렴 — 격자 세분 필요" 경고를 표시한다. 격자 적분은 엄밀 TIN 클리핑의 근사이므로 **근사임을 숨기지 않는다.**

**결과 표시 예**

```
구간 Sta.1200 ~ 1300 (급곡선 R=490)
 ├ 양단면평균법        절토 12,480 m³  성토  3,210 m³   (참조용)
 ├ 정밀법              절토 12,166 m³  성토  3,142 m³
 ├ 곡선보정 양단면      절토 11,905 m³  성토  3,088 m³
 └ 복합토량 ★기본값     절토 11,842 m³  성토  3,061 m³   격자 0.25m 수렴 ✓
   ⚠ 양단면평균법 대비 절토 +5.4% 과다 산출 — 곡선부 편심 미반영
```

**수용 기준**: 급곡선 구간(R ≤ 500 m)에서 양단면평균법과의 편차를 자동 산정하고, 편차 3% 초과 시 리포트에 **경고 배너**를 삽입한다.

### F-03 · 토량 변화율(L/C) 및 지층 분리 엔진 (P0)

**근거** 연구자료 §3 후반부, §2.5(지층 모델 연동)

**개념 정리**

| 상태 | 정의 | 기호 |
|---|---|---|
| 자연 상태 (Bank) | 굴착 전 원지반 체적 | `V_b` |
| 흐트러진 상태 (Loose) | 굴착·상차 후 체적 | `V_l = V_b × L` |
| 다져진 상태 (Compacted) | 성토·다짐 후 체적 | `V_c = V_b × C` |

**기본 계수(프로젝트 지질조사 결과로 반드시 대체)**

| 토질 | L (팽창) | C (다짐) | 비고 |
|---|---|---|---|
| 토사 | 1.20 ~ 1.30 | 0.85 ~ 0.90 | 기본 1.25 / 0.88 |
| 리핑암 | 1.30 ~ 1.50 | 1.10 ~ 1.30 | 기본 1.40 / 1.20 |
| 발파암 | 1.50 ~ 1.80 | 1.20 ~ 1.40 | 기본 1.65 / 1.30 |
| 특수토(폐석회 등) | 프로젝트 정의 | 프로젝트 정의 | 함수비·건조일 파라미터 별도 |

> ⚠ 위 값은 **앱의 초기 기본값**일 뿐이며, 실제 설계에는 해당 프로젝트의 토질조사보고서 및 적용 설계기준의 값을 입력해야 한다. 앱은 기본값 사용 시 리포트에 `기본계수 사용(미검증)` 배지를 명시한다.

**지층별 분리 산출**

```
측점별 strata[] 의 topEL 을 이용해 절토 깊이를 지층 구간으로 분할:
  절토_토사   = ∫ max(0, min(EG, 토사하한) - max(DG, 토사하한상위)) dA
  절토_리핑암 = ...
  절토_발파암 = ...
→ 지층별 L/C 적용 → 운반 대상 loose 체적, 성토 가능 compacted 체적 산출
→ 유용토(사용가능) vs 사토(폐기) 자동 분류
```

**출력 표 형식**

| 지층 | 절토(Bank) | 운반(Loose) | 성토전용(Comp.) | 유용 | 사토 |
|---|---|---|---|---|---|
| 토사 | 42,100 | 52,625 | 37,048 | 37,048 | 5,052 |
| 리핑암 | 18,300 | 25,620 | 21,960 | 21,960 | 0 |
| 발파암 | 9,450 | 15,593 | 12,285 | 12,285 | 0 |

### F-05 · 구조물 구간 코리더 타겟 스위칭 스크립트 생성 (P1)

**근거** 연구자료 §5.2

측점 메타데이터 `stype`(E/B/T/C)를 스캔하여 **전이 구간(Transition)** 을 자동 식별하고, 해당 구간의 비탈면 타겟을 지표면 → 구조물 형상선으로 전환하는 Dynamo 스크립트를 생성한다.

```python
# 생성기 출력 예 — Civil 3D Dynamo Python Node
# 구조물 구간 daylight 타겟 자동 스위칭
# -*- coding: utf-8 -*-
TRANSITIONS = [
    {"from": 1420.0, "to": 1680.0, "stype": "B", "target_fl": "FL-ABUT-A1"},
    {"from": 2310.0, "to": 2790.0, "stype": "T", "target_fl": "FL-PORTAL-T1"},
]

def switch_targets(corridor, transitions):
    for region in corridor.BaselineRegions:
        for tr in transitions:
            if region.StartStation >= tr["from"] and region.EndStation <= tr["to"]:
                for side in ("Left", "Right"):
                    tgt = region.GetTargets(side + "_Daylight")
                    tgt.TargetType = "FeatureLine"
                    tgt.TargetIds  = lookup_featureline(tr["target_fl"])
                    region.SetTargets(side + "_Daylight", tgt)
    corridor.Rebuild()      # ★ §4 자동 재구성 누락 방지 — 항상 명시 호출
```

**부가 게이트 연동**: G3에서 "구조물 구간(B/T)에 surface 타겟이 남아 있음"이 탐지되면 이 스크립트 생성 버튼이 **자동 강조**된다.

### F-06 · 점군/드론 EG 반입 및 횡단 슬라이스 (P1)

### F-07 · 토량 배분 최적화 · 매스 하울 다이어그램 (P1)

**근거** 연구자료 §2.4(중국 대규모 토공 최적 분배), §2.6(운반비 최소화)

**(a) 누가토량곡선(Mass Haul Diagram)**
```
누가토량 M(s) = Σ (절토_compacted-equivalent − 성토_required)  누적
평형선(Balance Line) 을 그어 free-haul(무료운반) / overhaul(초과운반) 구간 분리
```

**(b) 운반 배분 최적화**
- 목적함수: `min Σ (토량 × 운반거리 × 단가)` + 토취장 구입비 + 사토 처리비
- 제약: 토취장/사토장 용량, 지층별 성토 적합성, 구간별 필요 성토량
- 알고리즘: 소규모(≤50 구간)는 **탐욕적 최근접 배분 + 2-opt 개선**, 대규모는 **수송문제(Transportation Problem) 근사 해법**을 순수 JS로 구현

**(c) 특수토 처리 (한국 사례)**
폐석회 등 함수비가 높은 재료는 `dryingDays`, `moistureContent` 파라미터를 받아 **건조 대기에 따른 야적장 소요면적과 운반 지연일**을 별도 산출한다.

### F-08 · 배수 연계 검증 (P2)

**근거** 연구자료 §2.1 (Civil 3D ↔ InfoDrainage 심층 통합)

앱은 배수 해석을 수행하지 않는다. 대신 **횡단 형상이 배수 요구조건을 위배하지 않는지**만 검증한다.

| 항목 | 검증 룰(프로젝트에서 조정 가능) |
|---|---|
| 차도 횡단경사 | 설정 범위 내(기본 1.5% ~ 2.0%) |
| 길어깨 경사 | 차도 이상 |
| 측구 종단경사 | 최소 구배 미만 구간 연속 길이 탐지 |

### F-09 · Revit Toposolid 서브디비전 생성기 (P1)

**근거** 연구자료 §5.1

코리더 링크/형상선 외곽선을 JSON으로 내보내고, Revit에서 `Toposolid.CreateSubDivision()`을 호출해 **포장층·길어깨·식수대**를 논리 분할, 재질 매개변수를 자동 부여하는 스크립트를 생성한다. 연구자료의 스니펫을 **실사용 가능한 형태로 보강**한다(트랜잭션 관리, 예외 처리, 재질 ID 매핑, 좌표계 확인).

```python
# -*- coding: utf-8 -*-
# Node06 → Revit Toposolid Subdivision Generator (auto-generated)
# CRS: EPSG:{{epsg}}  |  Stations: {{staStart}} ~ {{staEnd}}
import clr
clr.AddReference('RevitAPI')
from Autodesk.Revit.DB import *

MATERIAL_MAP = {                 # 앱에서 주입
    "pavement": "ASPHALT_SURFACE_T50",
    "shoulder": "AGGREGATE_BASE",
    "planting": "TOPSOIL_PLANTING",
}

def create_subdivisions(doc, topo_id, loops_by_zone):
    created = {}
    t = Transaction(doc, "Node06 Corridor Subdivision")
    t.Start()
    try:
        for zone, loops in loops_by_zone.items():
            sub = Toposolid.CreateSubDivision(doc, topo_id, loops)
            p = sub.get_Parameter(BuiltInParameter.MATERIAL_ID_PARAM)
            mid = find_material_id(doc, MATERIAL_MAP.get(zone))
            if p and mid: p.Set(mid)
            created[zone] = sub.Id
        t.Commit()
    except Exception as ex:
        t.RollBack()                       # ★ 실패 시 문서 오염 방지
        raise Exception("Subdivision failed: %s" % str(ex))
    return created
```

### F-14 · 스크립트 생성기 하드닝 + 성능 프로파일 (P0)

**근거** 연구자료 §4(인코딩 파손·경로 공백·콜드스타트), §5.3(MMS 성능)

**(a) 인코딩·경로 방어**

| 위험 | 대응 |
|---|---|
| 한글 리터럴 파싱 실패 | 생성 시 `# -*- coding: utf-8 -*-` 삽입 + 한글 문자열 `\uXXXX` 이스케이프 옵션 |
| BOM 문제 | 플랫폼별 BOM 정책 분기(LISP/BAT는 BOM 없음, PowerShell은 UTF-8 BOM 권장) |
| 경로 공백/한글 | 모든 경로 리터럴 `"..."` 인용, BAT에 `chcp 65001` 선행 |
| 개행 코드 | Windows 대상 산출물은 CRLF 고정 |
| 경로 하드코딩 | `%~dp0` 상대경로 기반으로 생성 |

**(b) 콜드스타트 방어 (BAT 템플릿)**

```bat
@echo off
chcp 65001 > nul
setlocal
set "BASE=%~dp0"
set "PORT=8760"

rem --- 서버 헬스체크: 지수 백오프 (1s,2s,4s,8s,16s) ---
set DELAY=1
for /L %%i in (1,1,5) do (
    curl -s -o nul "http://127.0.0.1:%PORT%/health" && goto :READY
    timeout /t %DELAY% /nobreak > nul
    set /a DELAY=DELAY*2
)
echo [ERROR] 로컬 서버 응답 없음 - 포트 %PORT% 확인 필요
exit /b 1

:READY
"%BASE%run_node06.exe" --config "%BASE%config.json"
```

**(c) MMS 성능 루틴**
생성 스크립트 말미에 "작업 중 Surface LOD = Low → 내보내기 직전 High 전환 → 내보내기 → Low 복귀" 루틴을 옵션으로 삽입한다.

- 캔버스 **증분 렌더링** + 뷰포트 컬링

## 10. 결론

본 계획서는 연구자료 20개 핵심 항목을 앱 적용 관점에서 판정하여 **전면 적용 9건, 부분·축소·대체 적용 9건, 미적용 2건**으로 정리하고, 이를 14개 기능(F-01 ~ F-14)과 7개 게이트(G0 ~ G6)로 구체화하였다.

우선순위의 근거는 명확하다. 연구자료가 기술한 실패 사례의 파급력은 **좌표 합성 왜곡 > 체적 산출법 오류 > 토량 변화율 누락 > 스크립트 파손** 순이며, 앞의 세 가지는 발견 시점이 늦을수록 손실이 기하급수적으로 증가한다. 따라서 Node 06의 업그레이드는 화려한 시각화가 아니라 **"틀린 데이터를 통과시키지 않는 능력"** 에 자원을 집중해야 한다.

P0 단계(게이트 + 체적 엔진)만 완료해도 연구자료가 지목한 치명적 오류의 대부분을 앱 단계에서 차단할 수 있으며, P1·P2는 그 위에 하류 자동화와 분석 깊이를 쌓는 구조다.
