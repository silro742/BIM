# 클로드 코드 사용 가이드 초보자용

## 1. 시작하기 전에

### 지금 무슨 일이 있었나
  - 2026년 6월까지 로컬 PC에서 클로드와 작업했다
  - 8월에 작업 환경이 깃허브 기반으로 바뀌었다
  - 그 뒤 벼리팀과 앱성팀이 보이지 않게 되었다
  - 원인은 팀 기능이 꺼져 있었고 로컬 자료가 깃허브에 없었기 때문이다
  - 로컬 PC 파일은 지워지지 않았다

### 앞으로 어떻게 되나
  - 작업은 로컬 PC 토성 폴더에서 한다
  - 결과는 깃허브에 자동으로 보관한다
  - 팀 기능을 다시 켠다
  - 같은 일이 다시 생기지 않는다

### 알아둘 용어
  - 로컬 PC는 지금 쓰는 내 컴퓨터다
  - 클라우드는 인터넷 저쪽의 임시 컴퓨터다
  - 깃허브는 파일을 보관하고 이력을 남기는 곳이다
  - 커밋은 현재 상태를 하나의 기록으로 남기는 일이다
  - 푸시는 그 기록을 깃허브로 올리는 일이다
  - 브랜치는 작업 갈래다
  - 터미널은 명령어를 입력하는 검은 창이다

### 세 가지 저장 위치 구분
  - 토성 폴더는 실제 작업하는 곳이다
  - 깃허브는 백업과 이력 보관소다
  - 클라우드 세션은 임시 작업장이며 껐다 켜면 사라진다

## 2. 준비 작업

### 파워셸 여는 법
  - 키보드에서 윈도우 키를 누른다
  - powershell 이라고 입력한다
  - Windows PowerShell 을 클릭한다
  - 파란 창이나 검은 창이 열리면 성공이다
  - 창 왼쪽에 PS C 로 시작하는 글자가 보인다

### 스크립트 파일 저장 위치
  - 받은 ps1 파일 네 개를 한 폴더에 모은다
  - 바탕화면에 스크립트 라는 폴더를 만들어 넣으면 편하다
  - 파일 이름은 01 02 03 04 로 시작한다

### 그 폴더로 이동하는 법
  - 파워셸에 cd 를 입력하고 한 칸 띄운다
  - 폴더를 파워셸 창으로 끌어다 놓는다
  - 경로가 자동으로 입력된다
  - 엔터를 누른다

### 명령 입력 규칙
  - 명령은 한 줄로 입력하고 엔터를 누른다
  - 대소문자를 구분하지 않는다
  - 붙여넣기는 마우스 오른쪽 클릭이다
  - 오타가 나면 그냥 다시 입력하면 된다

## 3. 첫 번째 단계 설치하기

### 무엇을 하는가
  - 클로드 코드 프로그램을 PC에 설치한다
  - 팀 기능을 켜는 설정을 넣는다
  - 이미 설치되어 있으면 설정만 손댄다

### 실행 명령
  - powershell -ExecutionPolicy Bypass -File .\02_로컬복귀_설치.ps1

### 화면에서 보게 될 것
  - 1 3 클로드 코드 설치 확인 이라는 글자가 나온다
  - 설치되어 있지 않으면 진행할까요 라고 묻는다
  - Y 를 입력하고 엔터를 누른다
  - 설치가 몇 분 걸릴 수 있다
  - 2 3 에서 설정 파일을 백업하고 고친다
  - 3 3 에서 검증 결과를 보여준다

### 잘 되었는지 확인하는 법
  - 초록색 글씨 OK 가 여러 줄 보이면 성공이다
  - 마지막에 완료 라는 글자가 나온다
  - 파워셸 창을 닫았다가 다시 연다
  - claude --version 을 입력한다
  - 숫자로 된 버전이 나오면 설치된 것이다

### 이 단계에서 안전한 이유
  - 기존 설정 파일을 먼저 백업한다
  - 백업 파일 이름 끝에 날짜와 시각이 붙는다
  - 기존 설정을 지우지 않고 항목만 더한다

## 4. 두 번째 단계 진단하기

### 무엇을 하는가
  - 벼리팀과 앱성팀의 흔적을 PC 전체에서 찾는다
  - 결과를 바탕화면에 보고서로 저장한다

### 실행 명령
  - powershell -ExecutionPolicy Bypass -File .\01_진단_벼리팀찾기.ps1

### 이 단계가 안전한 이유
  - 읽기만 한다
  - 파일을 고치거나 지우지 않는다
  - 몇 번을 실행해도 상관없다

### 화면에서 보게 될 것
  - 1 부터 8 까지 번호가 붙은 항목이 차례로 나온다
  - 3 번은 팀원 역할 정의를 찾는다
  - 5 번은 팀 작업 목록을 찾는다
  - 6 번은 지난 대화 기록을 찾는다
  - 7 번은 토성 폴더 내용을 보여준다

### 결과 확인하는 법
  - 바탕화면에 벼리팀_진단결과 로 시작하는 txt 파일이 생긴다
  - 그 파일을 더블클릭해서 연다
  - 내용을 전체 선택해 복사한다
  - 클로드에게 붙여넣어 준다

### 결과가 뜻하는 것
  - 3 번에 파일이 있으면 역할 정의가 살아 있다
  - 5 번에 6월 폴더가 있으면 팀 작업 내용이 남아 있다
  - 6 번에 기록이 있으면 지난 대화가 남아 있다
  - 모두 없음이면 팀이 세션과 함께 사라진 것이다
  - 모두 없음이어도 문제가 아니라 새로 만들면 된다

## 5. 세 번째 단계 깃허브에 올리기

### 무엇을 하는가
  - 토성 폴더 내용을 깃허브에 전부 올린다
  - 깃허브 내용을 로컬과 똑같이 만든다
  - 앞으로 백업이 자동으로 쌓이기 시작한다

### 실행 명령
  - powershell -ExecutionPolicy Bypass -File .\04_로컬을_깃허브에_반영.ps1

### 실행 전에 알아둘 것
  - 로컬 토성 폴더가 원본이 된다
  - 깃허브에 있던 예전 내용은 참고하지 않는다
  - 다만 예전 기록은 이력에 남아 되돌릴 수 있다

### 화면에서 보게 될 것
  - 1 6 사전 확인에서 폴더를 찾는다
  - 처음이면 자동으로 깃허브에 연결한다
  - 인증 창이 뜨면 깃허브 계정으로 로그인한다
  - 2 6 에서 너무 큰 파일이 있는지 검사한다
  - 3 6 에서 팀 기능 설정 파일을 만든다
  - 4 6 에서 무엇이 바뀌는지 목록을 보여준다
  - 5 6 에서 진행할까요 라고 묻는다
  - 6 6 에서 커밋하고 올린다

### 확인 화면 읽는 법
  - 초록색 추가는 새로 올라갈 파일이다
  - 노란색 수정은 내용이 바뀔 파일이다
  - 빨간색 삭제는 깃허브에서 없어질 파일이다
  - 삭제 목록을 눈으로 한 번 확인한다
  - 문제 없으면 Y 를 입력하고 엔터를 누른다
  - 이상하면 N 을 입력하면 아무 일도 일어나지 않는다

### 잘 되었는지 확인하는 법
  - 마지막에 완료 라는 글자가 나온다
  - 브라우저에서 github.com/silro742/BIM 을 연다
  - 토성 폴더와 같은 파일들이 보이면 성공이다

### 실패했을 때
  - 인증 창에서 로그인을 다시 한다
  - 파일이 100MB를 넘으면 그 파일을 폴더 밖으로 옮긴다
  - 네트워크가 끊기면 스크립트가 알아서 네 번 재시도한다
  - 그래도 안 되면 화면 내용을 그대로 클로드에게 알려준다

## 6. 매일 쓰는 방법

### 작업 시작할 때
  - 파워셸을 연다
  - cd "$env:USERPROFILE\Desktop\토성" 을 입력한다
  - claude 를 입력한다
  - 클로드가 준비되면 그냥 한국어로 말하면 된다

### 작업 끝낼 때
  - 커밋하고 푸시해줘 라고 말한다
  - 이 한 마디가 백업이다
  - 하루에 여러 번 해도 좋다

### 이것만 지키면 되는 원칙
  - 작업은 로컬에서 한다
  - 결과는 반드시 깃허브에 올린다
  - 올리지 않은 것은 없어질 수 있다

### 클로드 끝내는 법
  - exit 를 입력한다
  - 또는 컨트롤 키와 C 를 두 번 누른다

## 7. 클로드에게 말하는 방법

### 기본 원칙
  - 한국어로 평소처럼 말하면 된다
  - 명령어를 외울 필요가 없다
  - 파일 이름을 정확히 몰라도 된다

### 파일 작업 예시
  - 06 표준횡단 앱을 열어서 무슨 기능이 있는지 알려줘
  - 07 배수 앱에서 계산이 틀린 부분을 찾아줘
  - 토성 폴더에 뭐가 들어있는지 정리해줘

### 깃허브 작업 예시
  - 커밋하고 푸시해줘
  - 지금까지 바뀐 내용을 보여줘
  - 어제 상태로 되돌려줘
  - 새 브랜치를 만들어서 거기에 올려줘

### 검토 요청 예시
  - 이 앱에서 오류가 날 만한 곳을 찾아줘
  - 법령 근거가 맞는지 확인해줘
  - 확인 안 되는 것은 확인 불가라고 표시해줘

### 잘 말하는 요령
  - 무엇을 원하는지 먼저 말한다
  - 어느 파일인지 알려주면 더 정확하다
  - 하지 말아야 할 것도 같이 말하면 좋다
  - 결과 형식을 정해주면 그대로 만든다

## 8. 팀 기능 사용하기

### 팀이 무엇인가
  - 여러 클로드가 동시에 다른 일을 맡는 것이다
  - 각자 따로 생각하고 서로 대화한다
  - 벼리팀 앱성팀이 이 기능이었다

### 팀을 부르는 법
  - 팀원 세 명을 띄워서 06 앱을 각각 다른 관점으로 검토해줘
  - 이렇게 말하면 클로드가 알아서 팀을 만든다

### 팀원 보는 법
  - 입력창 아래에 팀원 목록이 나온다
  - 위아래 화살표로 고른다
  - 엔터를 누르면 그 팀원 화면으로 들어간다
  - 그 팀원에게 직접 말할 수 있다

### 팀에 대해 알아야 할 사실
  - 팀은 세션 하나에만 존재한다
  - 클로드를 끄면 팀은 사라진다
  - 이것은 고장이 아니라 원래 그런 구조다
  - 벼리팀이 사라진 것도 이 때문이다

### 팀을 매번 되살리는 법
  - 역할을 파일로 만들어 두면 된다
  - 토성 폴더 안 .claude 폴더 안 agents 폴더에 넣는다
  - 벼리.md 같은 이름으로 저장한다
  - 다음부터 벼리 타입으로 팀원을 띄워줘 라고 하면 된다
  - 이 파일은 깃허브에 올라가므로 없어지지 않는다

### 역할 파일 만드는 법
  - 클로드에게 벼리팀 역할 파일을 만들어줘 라고 말한다
  - 어떤 일을 시키고 싶은지 설명한다
  - 클로드가 형식에 맞게 만들어 준다

## 9. 자주 생기는 문제

### claude 를 찾을 수 없다고 나올 때
  - 파워셸 창을 닫고 다시 연다
  - 그래도 안 되면 02번 스크립트를 다시 실행한다

### 스크립트 실행이 막힐 때
  - 명령 앞에 powershell -ExecutionPolicy Bypass -File 을 꼭 붙인다
  - 파일을 더블클릭하지 말고 이 방식으로 실행한다

### 한글이 깨져 보일 때
  - 파워셸 창 제목을 오른쪽 클릭해 속성을 연다
  - 글꼴을 굴림체나 D2Coding 으로 바꾼다

### 깃허브 인증 창이 계속 뜰 때
  - 처음 한 번은 반드시 로그인해야 한다
  - 로그인 후에는 다시 묻지 않는다

### 파일이 너무 크다고 할 때
  - 100MB 넘는 파일은 깃허브가 받지 않는다
  - 그 파일을 토성 폴더 밖으로 옮긴다
  - 04번을 다시 실행한다

### 실수로 파일을 지웠을 때
  - 깃허브에 올린 뒤라면 되돌릴 수 있다
  - 클로드에게 어제 상태로 되돌려줘 라고 말한다

### 무엇을 해야 할지 모를 때
  - 클로드에게 지금 상황을 설명하고 물어본다
  - 화면에 나온 글자를 그대로 붙여넣으면 된다

## 10. 하지 말아야 할 것

### 위험한 행동
  - 브랜치를 함부로 지우지 않는다
  - .git 폴더를 손으로 지우지 않는다
  - 무슨 뜻인지 모르는 명령을 붙여넣지 않는다

### 습관으로 피할 것
  - 며칠씩 커밋하지 않고 작업하지 않는다
  - 같은 파일을 여러 폴더에 복사해 두지 않는다
  - 버전 번호를 임의로 바꾸지 않는다

### 클라우드 세션에서 주의할 것
  - 클라우드는 깃허브에 올린 것만 볼 수 있다
  - 클라우드에서 만든 것은 푸시해야 남는다
  - 로컬 파일은 클라우드에서 보이지 않는다

  - 04번 스크립트로 깃허브에 올린다
