## 2. 원인 (확정)

세 가지가 겹쳤습니다. 순서대로 결정적입니다.

### 2-1. Agent Teams 기능이 클라우드 세션에서 꺼져 있음

"팀"은 별명이 아니라 Claude Code 의 **Agent Teams** 기능입니다. 이 기능은 기본값이 **비활성**입니다.

공식 문서:

> Agent teams are disabled by default. Enable them by setting `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`.
> Without that variable, **no team is set up at session start, no team directories are written,
> and Claude does not spawn or propose teammates.**

클라우드 세션에서 직접 확인한 값:

```
CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS = []      (비어 있음)
~/.claude/teams/                        없음
~/.claude/tasks/                        없음
```

즉 현재 환경에서는 팀이 숨겨진 것이 아니라 **팀이라는 개념 자체가 작동하지 않습니다.**

### 2-2. 팀은 원래 세션을 넘어 살아남지 못함

| 문서상 사실 | 의미 |
|---|---|
| `One team per session` — 세션 1개에 팀 1개, 세션 간 공유 불가 | 새 세션에서 옛 팀을 부를 수 없음 |
| 팀 이름은 `session-` + 세션 ID 앞 8자 로 자동 생성 | 사람이 이름을 고정할 수 없음 |
| 팀 설정 디렉터리는 **세션 종료 시 삭제** | 팀 자체는 소멸이 정상 동작 |
| 작업 목록은 **로컬에만 남고 절대 업로드되지 않음** | 클라우드로 옮겨올 방법이 원천적으로 없음 |
| `/resume` 와 `/rewind` 로 팀원이 복원되지 않음 | 되살리기 불가 |

**따라서 벼리팀·앱성팀의 소실은 고장이 아니라 설계상 예정된 동작입니다.**
깃허브 전환은 이 사실을 드러낸 계기였습니다.

### 2-3. 저장소에 아무것도 커밋되어 있지 않았음

# 부록 — 로컬 PC와 GitHub 양쪽에서 동시에 활동하는 방법

## 구조

핵심은 **토성 폴더 자체를 깃 작업 폴더로 만드는 것**입니다.

```
C:\Users\silro\Desktop\토성\        <- 로컬 파일 (직접 읽기·쓰기)
        └── .git\                   <- 여기에 연결이 생김
                ↕  push / pull
        github.com/silro742/BIM
```

이렇게 하면 **세션 하나**가 양쪽을 모두 다룹니다.

| 하는 일 | 어디에 작용 |
|---|---|
| 파일 읽기·수정·생성 | 로컬 토성 폴더 |
| 앱 실행·테스트 | 로컬 PC |
| 커밋·푸시·풀 | GitHub |
| 브랜치·PR 확인 | GitHub |

별도 설정이 필요 없습니다. 로컬 Claude 는 `git` 명령을 그대로 쓸 수 있기 때문에,
폴더가 저장소에 연결되어 있기만 하면 양쪽이 자동으로 이어집니다.

## 연결 방법

`tools\03_토성_깃허브_연결.ps1` 을 실행합니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\03_토성_깃허브_연결.ps1
```

동작:

1. `git init` 후 원격을 `silro742/BIM` 으로 등록
2. 원격 이력을 가져옴
3. `git reset` 으로 **인덱스만** 저장소에 맞춤 — 작업 파일은 손대지 않음
4. 연결 전후 파일 수를 비교해 검증하고 현황 출력

**비파괴성 검증 완료.** 저장소와 이름이 겹치는 파일, 로컬 전용 파일, 하위 폴더를 만들어
동일 시퀀스를 실행한 결과 모든 파일의 내용이 그대로였고(체크섬 동일) 삭제된 것이 없었습니다.

되돌리려면 `.git` 폴더만 지우면 연결 전 상태입니다.

## 로컬과 클라우드 세션을 오가는 3가지 다리

연결과는 별개로, 세션 자체를 이동시키는 방법이 있습니다.

### 1. 로컬 -> 클라우드 : `claude --cloud`

로컬에서 작업하다가 오래 걸리는 일만 클라우드로 넘깁니다.

```bash
claude --cloud "07 배수 앱 전체 테스트 돌리고 실패 수정해줘"
```

클라우드 VM 은 **로컬 체크아웃이 아니라 깃허브 원격을 복제**하므로,
로컬 커밋이 있으면 먼저 푸시해야 합니다.

여러 개를 동시에 띄울 수 있고 `/tasks` 로 진행 상황을 봅니다.

### 2. 클라우드 -> 로컬 : `claude --teleport`

클라우드 세션을 대화 기록째로 로컬 터미널로 끌어옵니다.

```bash
claude --teleport              # 목록에서 고르기
claude --teleport <세션ID>     # 특정 세션 바로
```

조건: 같은 저장소의 체크아웃에서 실행, 작업 트리가 깨끗함, 해당 브랜치가 원격에 푸시되어 있음, 동일 계정.

### 3. 로컬 세션을 웹·폰에서 보기 : `/remote-control`

로컬 세션 안에서 실행하면, **로컬 PC 에서 실행되면서**(= 파일 전체 접근)
웹과 모바일 앱에서 진행 상황을 보고 지시를 보낼 수 있습니다.

클라우드의 편의만 얹고 로컬의 권한은 그대로 유지하는 방식입니다.

## 권장 조합

```
평소 작업      : 토성 폴더에서 로컬 claude  (파일 전체 접근 + 깃허브)
외출 중 확인   : /remote-control 로 폰에서 모니터링
오래 걸리는 일 : claude --cloud 로 넘기고 로컬은 계속 작업
결과 이어받기  : claude --teleport 로 로컬로 가져옴
```

## 주의할 차이

| | 로컬 세션 | 클라우드 세션 |
|---|---|---|
| 파일 접근 | PC 전체 (실행한 폴더 기준) | 저장소에 커밋된 것만 |
| `~/.claude` 자산 | 그대로 사용 | 매번 초기화 |
| Agent Teams | `settings.json` 으로 켬 | 저장소 `.claude/settings.json` 으로 켬 (이미 적용됨) |
| 앱 실행·스크린샷 | 가능 | 리눅스 컨테이너 한정 |
| 지속성 | PC 에 남음 | 컨테이너 회수 시 소멸, 푸시한 것만 남음 |

**깃허브에 커밋되지 않은 것은 클라우드 세션에 존재하지 않습니다.**
이번 벼리팀 건의 근본 원인이 바로 이것이었습니다.

# 부록 2 — 로컬을 기준으로 GitHub 전체 덮어쓰기

## 결정 사항

로컬 토성 폴더를 **원본(기준)** 으로 확정합니다.
저장소의 기존 내용은 참고하지 않고, 로컬 내용으로 전부 교체합니다.

## 방식 — force push 를 쓰지 않는 이유

"덮어쓰기" 에는 두 가지가 있습니다.

| 방식 | 결과물 | 되돌리기 |
|---|---|---|
| **일반 커밋으로 교체** (채택) | 로컬 내용과 100% 동일 | 가능 |
| force push 로 이력 삭제 | 로컬 내용과 100% 동일 | 불가능 |

**결과물이 완전히 같습니다.** 차이는 되돌릴 수 있느냐 뿐입니다.
그래서 일반 커밋을 씁니다. 잃는 것 없이 안전망만 생깁니다.

## 실행

```powershell
powershell -ExecutionPolicy Bypass -File .\04_로컬을_깃허브에_반영.ps1
```

확인 절차 없이 바로 진행하려면 `-Yes` 를 붙입니다.

## 스크립트가 하는 일

1. **연결 확인** — 아직 저장소에 연결되지 않았으면 자동으로 연결합니다.
   03번을 따로 실행할 필요가 없습니다.
2. **대용량 파일 검사** — GitHub 은 100MB 초과 파일을 거부합니다.
   95MB 초과 파일이 있으면 푸시 전에 멈추고 알려줍니다.
3. **팀 기능 설정** — 토성 폴더에 `.claude\settings.json` 이 없으면 생성합니다.
   이 파일이 있어야 벼리팀 같은 팀 기능이 동작합니다.
   로컬 내용만 그대로 반영하려면 `-PureOverwrite` 를 붙입니다.
4. **변경 내용 산출** — 추가/수정/삭제 건수를 세고, **삭제될 파일은 전부 나열**합니다.

6. **커밋 및 푸시** — 네트워크 실패 시 2·4·8·16초 간격으로 4회 재시도합니다.
