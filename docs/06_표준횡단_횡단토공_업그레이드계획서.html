00전제와 범위

원본 앱 소스를 직접 열람하지 않은 상태에서의 설계 계획임을 먼저 밝힌다.

이 계획의 근거 두 가지

① 연구자료가 서술하는 Node 06의 역할 — 상류(선형·종단)에서 JSON을 받아 표준횡단과 횡단토공을 검증하고, 하류(배수·포장·구조)로 파라미터를 전달하는 자동화 게이트키퍼. 로컬 HTTP 포트를 통해 Dynamo · AutoCAD LISP · Revit 저널 스크립트를 생성·구동한다.

② 동일 계열 앱의 실제 구조 — 저장소의 BIM_Slope_EL_Automation.html(962행, 단일 파일)에서 확인한 패턴: steps[] 기반 좌측 워크플로우 내비, 캔버스 + 우측 패널 2열, REGULATIONS[] + checkCompliance() 법규 게이트, SCRIPT_TEMPLATES{} 생성기와 downloadScript(), 외부 의존성 0의 오프라인 구동.

실제 소스 확인 후에는 함수 배치(구현 위치)만 재매핑하면 되며, 기능 명세 · 수용기준 · 데이터 스키마는 그대로 유효하다.

범위 안 — 단일 파일 HTML 앱 내부의 계산 엔진, 검증 게이트, 화면 단계, 스크립트 생성기, JSON 스키마, 견고성과 성능.
범위 밖 — Civil 3D · Revit 본체 애드인 개발, 서버 인프라 구축, 유상 도구 도입.

02목표와 설계 원칙

무엇을 지키기 위한 업그레이드인가.

목표

  • O1 · 무결성 우선 — 좌표 · 타겟 · 체적 3대 오염원을 앱이 차단한다. 경고가 아니라 게이트다.
  • O2 · 물량 신뢰도 — 기하 체적에서 시공 체적으로 격상(토량변화율 반영, 운반 계획 연동).
  • O3 · 파이프라인 연속성 — 상·하류 데이터가 JSON · LandXML · IFC 4.3 표준 스키마로만 유동.
  • O4 · 반복 작업 제거 — 구조물 구간 타겟 스위칭, 지형 분할, LOD 제어를 스크립트로 자동 생성.
  • O5 · 견고성 — 한글 경로 · 공백 경로 · 콜드스타트에서 실패하지 않는다.

설계 원칙

  1. 단일 파일 유지 — 외부 CDN과 빌드 도구 없이 오프라인 더블클릭 구동(현장 보안망 대응).
  2. 게이트는 하드 블록 — P0 위반 시 하류 내보내기 버튼을 disabled 처리.
  3. 계수 하드코딩 금지 — 모든 기준값은 편집 가능한 PARAMS 객체 + 프로젝트 JSON 오버라이드.
  4. 산출값에 출처 표기 — 결과 카드마다 산출 기법(AEA / Prismoidal / Composite TIN)과 신뢰도 배지.
  5. 스키마 버저닝 — 모든 입출력 JSON에 schema_version, 하위 호환 파서 유지.

04기능 명세

우선순위 — P0 차단 게이트, 즉시 · P1 핵심 계산과 자동화 · P2 상호운용과 고도화

F-01

좌표계 무결성 게이트

P0
§4 — “가장 대표적이고 파괴적인 오류는 좌표 합성 왜곡”

상류 JSON 로드 시 project.crs.epsg를 최우선 검사하고, 한국 투영 좌표 화이트리스트(5186 중부 · 5185 서부 · 5187 동부 · 5188 동해 · 5179 UTM-K)와 대조한다. 다음 휴리스틱 중 하나라도 참이면 합성좌표로 판정한다.

  • 측점 실좌표 필드 결측
  • 선형에 곡선 요소가 있는데 모든 좌표가 완전 직선상 정렬(잔차 RMS < 1e-6 m) — 가장 결정적인 지표
  • 좌표가 국내 투영 유효 범위(N 100,000–800,000 / E 0–400,000) 이탈
  • 원점이 (0,0) 근방 ±1,000 m — 상대좌표 의심

판정 시 적색 배너, 하류 내보내기 전면 차단, 측점 비고란 좌표합성(Synthesized) 태그, 상류 재발행 요청문 자동 생성.

function detectSynthesizedCRS(data){
  const f=[], secs=data.sections||[];
  if(!data.project?.crs?.epsg) f.push("EPSG 코드 미기재");
  const hasCurve=(data.alignment?.elements||[]).some(e=>e.type!=="line");
  const pts=secs.filter(s=>Number.isFinite(s.northing)&&Number.isFinite(s.easting));
  if(pts.length<secs.length) f.push("측점 실좌표 결측");
  if(pts.length>=3){
    const n=pts.length,
          mx=pts.reduce((a,p)=>a+p.easting,0)/n,
          my=pts.reduce((a,p)=>a+p.northing,0)/n;
    let sxx=0,sxy=0;
    pts.forEach(p=>{sxx+=(p.easting-mx)**2; sxy+=(p.easting-mx)*(p.northing-my);});
    const k=sxx?sxy/sxx:0;
    const rms=Math.sqrt(pts.reduce((a,p)=>
      a+((p.northing-my)-k*(p.easting-mx))**2,0)/n);
    if(hasCurve && rms<1e-6) f.push("곡선 선형인데 좌표가 완전 직선 → 합성좌표 강력 의심");
  }
  return {synthesized:f.length>0, reasons:f};
}
수용기준
  • 곡선 포함 + 좌표 결측 샘플에서 내보내기 버튼 disabled, 사유 3건 이상 표시
  • EPSG:5186 + 실좌표 정상 샘플은 무경고 통과
  • 판정 결과가 출력 JSON gates.blocking에 기록
F-02

체적 산출 3중 엔진과 복합토량 강제

P0
§3 — 양단면평균법은 급곡선 · 교차로에서 “수만 ㎥ 단위 오차”를 낳는다

세 기법을 모두 계산해 나란히 비교 표시한다.

  • 양단면평균법 V = (A1+A2)/2 × L
  • 정밀법 V = L/6 × (A1 + 4·Am + A2)
  • 복합토량 V = Σ(삼각형 면적 × 평균 절·성 깊이)

곡선부 편심 보정(Pappus 정리) — 반경 R 구간에서 단면 도심이 곡률 중심 반대쪽으로 e만큼 치우치면 V' = V × (1 + e/R), 곡률 중심 쪽이면 1 − e/R. 편측 확폭 · 편경사 구간에서 필수.

불일치 경보 — AEA와 Composite TIN 차이가 3% 초과 시 황색, 7% 초과 시 적색 + 해당 구간 하이라이트. 하류 전달값은 Composite TIN만 허용하며 AEA 선택 시 차단(G-02-METHOD).

계산상 주의

영단면 교차 삼각형(절·성 혼재)은 반드시 교선으로 세분해야 한다. 단순 평균 깊이를 쓰면 절토와 성토가 서로 상쇄되어 물량이 과소 산출된다.

수용기준
  • 직선 구간 샘플에서 3기법 편차 < 1%
  • R=60 m 급곡선 + 편측 확폭 샘플에서 차이가 정량 표기되고 적색 경보 발생
  • 곡률 보정 on/off 결과가 각각 표기
F-03

코리더 타겟 · 리빌드 신선도 검사

P0

필수 고지

위 값은 설계 착수용 기본값이다. 반드시 프로젝트 토질조사 보고서 값으로 대체하도록 UI에 고지하고, 미대체 시 산출 결과에 “기본계수 사용” 배지를 부착한다.

계산 규칙은 자연상태(Bank) 기준으로 통일한다. 성토 소요 자연토량 V_bank = V_compacted / C, 운반 토량 V_loose = V_bank × L.

누가토량곡선을 신설해 x축 측점 · y축 누가 토량으로 유용 구간, 토취장, 사토장을 색으로 구분하고 평균 운반거리와 무상 운반거리 초과분을 산출한다.
